# 값 대조 — 시안 값 ↔ 개발 값

PC 웹 검수는 그림을 겹쳐 보는 것이 아니라 **값을 견주는 것**이다.
색·글꼴·글자크기·굵기·모서리·테두리·크기를 숫자로 맞춰 보고, 다른 곳을 **후보**로 올린다.

**여기서 나오는 것은 지적이 아니라 후보다.** 지적으로 올리는 것은 사람이 포털에서 누른다(CLAUDE.md 2번-2).

## 한 번 돌려 보기

```
python3 -m valueqa 시안.json 개발.값.json --지시서 수정요청.md --보기 결과.html \
  --화면키 CV-WEB-012 --화면이름 "체류시간 관리" --주소 https://내부/stay --차수 1
```

- `시안.json` — 촬영 준비 플러그인이 보낸 검수요소 꾸러미, 또는 이미 값 대조 모양인 것. 알아서 구분한다.
- `개발.값.json` — 자동 캡쳐가 화면마다 남기는 `*.값.json`.
- `--지시서` — **퍼블리싱·개발에 그대로 넘기는 수정 요청(Markdown).** 아래 참조.
- `--보기` — 디자이너가 눈으로 훑는 한 장(HTML). `-o` 는 후보를 JSON 으로 저장한다.

## 무엇을 내보내나 — 지시서가 기본이다

값 검수의 결과물은 '보는 문서'가 아니라 **고치는 문서**다(`fixdoc.py`).

- **한꺼번에 고칠 것** — 여러 곳을 같은 값으로 맞추면 되는 것은 한 줄로 묶어 준다. 일괄 반영용.
- **고칠 항목** — 고칠 것마다 `{화면키}-{번호}` 가 붙는다. **고칠 자리는 개발 화면 기준**이다 —
  `#id` 또는 `section.stats > div.card` 같은 CSS 선택자, 그 요소의 글자, 화면 안 자리(위쪽 오른편 등).
  디자인 레이어 이름은 맨 뒤에 〈시안 …〉 로 보조로만 적는다(디자이너가 되짚을 때 쓴다).
  화면 이름도 개발 화면 제목과 주소를 앞세운다 — 시안 프레임 이름은 디자이너가 임의로 붙인 것이라
  개발·퍼블리싱이 못 알아본다.
- **그대로 붙여 쓰는 값** — 요소별 CSS 덩어리. 주석에 번호와 자리가 들어간다.
- **구조** — 디자인에 없는데 있는 것 / 있는데 못 찾은 것.
- **고친 뒤 확인** — 번호가 붙은 체크 목록. 체크된 것만 다음 차수에서 다시 잰다.

화면 여러 개를 한 문서로 내려면 `지시서묶음([(결과, {"화면키":…, "화면이름":…, "주소":…}), …])`.
**화면이 달라도 같은 고침은 맨 앞 '한꺼번에 고칠 것' 에 함께 묶인다** — 여러 화면을 한 번에 반영하라고.

순서를 이렇게 두는 이유: 값은 기계가 정확히 짚어 준다.
**값부터 한 번에 바로잡아 놓고, 그다음 그림·배치를 눈으로 보는 검수를 최소한만** 하면 된다.

## 세 걸음

| 걸음 | 파일 | 하는 일 |
|---|---|---|
| 자리 실마리 | `../plugin-value-qa/collect-core.js` | 잴 때 요소의 `id` 와 CSS 선택자(`sel`)까지 함께 적는다 (core-1.2) |
| 시안 값 받기 | `design.py` | 플러그인이 보낸 검수요소를 값 대조가 읽는 모양으로 (피그마 토큰 안 씀) |
| 짝 맞추기 | `match.py` | 이름표 없이 글자·자리·크기·종류로 잇는다 |
| 값 견주기 | `compare.py` | 속성을 하나씩 대조하고 합·불을 매긴다 |
| 후보 올리기 | `candidates.py` | 값다름 · 더있음 · 빠짐 세 갈래로, 신뢰도와 함께 |
| 고치게 하기 | `fixdoc.py` | 개발·퍼블리싱이 일괄 반영하는 수정 요청(Markdown) |
| 눈으로 보기 | `report_html.py` | 디자이너가 훑는 한 장짜리 화면 |

알고리즘은 이미 검증된 `plugin-value-qa/ui.html` 을 그대로 옮긴 것이다. 새로 지어내지 않았다.
한쪽을 고치면 다른 쪽도 고치고, 자가검사 7번(셈 같음)으로 어긋남을 잡는다.

## 일부러 빼는 것

- **안쪽여백(padding)** — 재기는 하되 후보로 올리지 않는다. 퍼블리싱 단계에서 걸러진다(CLAUDE.md 8번).
- **위치(x·y)** — 늘 '참고'. 디자인 목업과 실제 페이지는 높이가 달라 쉽게 어긋난다.
- **크기(너비·높이)** — 시안과 개발의 화면 폭이 다르면 참고로 내린다.
- **아이콘 조각** — 작은 벡터는 뺀다. 개발화면은 아이콘을 그림 하나로 그려서 값 비교가 안 된다.

## 아직 안 한 것

- 회사 토큰·컴포넌트 규정 대조 (정본: `github.com/s1designux/S1-UX-DESIGN-with-AI` 의 `registry/`)
- 흐름 검수 — 어떤 버튼을 누르면 어느 화면이 나오는지
- 포털 붙이기 — 후보를 `auto_candidate` 에 넣기 (포털 쪽 코드는 `main` 가지에 있다)
