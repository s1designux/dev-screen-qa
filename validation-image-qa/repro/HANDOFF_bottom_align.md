# 인수인계 — 푸터·하단 내용의 자리 맞추기

**한 줄:** 페이지 상세에서 번호를 누르면 뜨는 '나란히 보기'가, 화면 **아래쪽(푸터·하단 고정 영역)** 에서는
시안 쪽 조각을 제 자리에서 못 잘라 온다. 위·가운데는 맞는다. 이 조각에서 그 아래쪽을 맞추는 방법을 찾는다.

## 지금까지 (커밋 258b91a)

번호·검수 카드를 누르면 커서 옆에 디자인·개발 조각이 나란히 뜬다(`mvp0/comparison_view.py`의 `qaCompareIssue`).
시안 쪽 자리는 **세 단계**로 찾는다.

1. **요소별 자리** — 검수기가 후보마다 저장해 둔 `auto_candidate.design_box`
   (포털이 `overlay_json`으로 내려보내고, 지적으로 등록하면 그 지적 번호에도 같은 자리를 매단다).
2. **가늠한 밀림** — 두 그림을 가로 320px로 줄여 **줄마다 잉크 양**을 재고(`profileOf`),
   그 요소가 있는 구간의 무늬를 시안 무늬 위에서 밀어 보며 가장 닮은 자리를 찾는다(`guessShift`, ZNCC · 멀리 갈수록 벌점).
3. **화면 전체 맞춤값** — 검수기가 회차에 저장한 `auto_run.alignment`(s·tx·ty).

둘 다 빈 자리면 쪽지에 "두 그림 모두 비어 있어요" 한 줄이 뜬다.

## 남은 문제 (여기서부터)

원인이 **둘**이다. 섞어서 보지 말 것.

**(가) 가늠이 하단에서 약하다.** 푸터는 글자가 옅고 가늘어 줄 잉크가 작다. 아래쪽 여백이 길면
여러 자리가 비슷하게 닮아 엉뚱한 줄에 붙거나, 문턱(0.5)을 못 넘어 3단계로 떨어진다.
또 시안과 개발의 **페이지 총 높이가 다르면** 푸터는 '위에서 몇 px'이 아니라 '아래에서 몇 px'에 있다 —
지금 셈은 전부 위 기준이다.

**(나) 핀 값 자체가 빈 자리를 가리킨다.** 옛 PDF 결과서에서 옮겨온 화면은 사람이 어림해 찍은 좌표라
개발 그림에도 아무것도 없는 자리를 가리킨다. 이건 그림 문제가 아니라 **데이터 문제**라 가늠으로 못 고친다.
사람이 핀을 끌어 옮기는 길(대기열 6번 '포털에서 직접 네모 치기')로만 풀린다.

## 한 것 (2026-09-14)

**(가) 는 끝났다.** 낱개 요소가 시안 전체를 훑던 것을 그만두고, **화면 한 벌마다 '밀림 후보'를 먼저 세운 뒤
그 언저리(±2%)에서만 고르게** 했다(`mvp0/comparison_view.py` 의 `pageShifts`). 후보는 다섯이다.

| 후보 | 어떻게 구하나 | 자리 |
|---|---|---|
| 정렬 | 검수기가 회차에 저장한 `auto_run.alignment` 의 ty에서 **엔진이 잘라낸 위쪽 띠(`range.captureTop`)를 되돌린 값** | 화면 전체 |
| 위 | 개발 그림 **위쪽 절반**의 줄무늬를 시안에서 찾은 값 | 위 |
| 아래 | 개발 그림 **아래쪽 1/3**의 줄무늬를 시안에서 찾은 값 | 아래 |
| 바닥 | 두 그림의 **마지막 잉크 줄**끼리 맞춘 값 (문턱 1% — 푸터 잔글씨가 아주 옅다) | 아래 |
| 아래끝 | 두 그림의 **아래끝**끼리 맞춘 값(배경이 흰색이 아닐 때의 버팀목) | 아래 |

요소마다 그 언저리를 다시 재서 가장 닮은 것을 고르고, 어느 것도 문턱(0.5)을 못 넘으면 **옮기지 않고**
그 자리(위/아래)에 맞는 화면 전체 값을 그대로 쓴다.

바로잡은 것 둘: **맞춤값이 잘린 그림 기준**이라 포털이 그대로 쓰면 위쪽 띠만큼 어긋났다
(`auto_inspect` 가 `data-actop` 으로 함께 내려보낸다). 그림이 바뀌면 줄무늬를 다시 잰다.

성적: 재현 세트 **21/36 → 36/36**. 실제 화면 8개·핀 66개는 **같은 자리**(회귀 없음).
재현 세트는 `bottom_align.py` · `bottom_align.harness.html` (README 참조).

## 남은 것 — (나) 핀 값 자체가 빈 자리를 가리킨다

가늠으로는 못 고친다. 지금은 쪽지에 **어느 쪽이 비었는지** 적어 둔다
(둘 다 / 개발 그림 쪽 / 시안 쪽). 실제로 고치려면 대기열 6번 **'포털에서 직접 네모 치기'** 가 필요하다.
TB-WEB-001 의 푸터 핀 3개가 여기 해당한다.

## 아직 안 한 것

- **세로줄 무늬로 x도 확인** — 좌우가 다른 앱 화면(가변폭). 지금은 x를 폭 비율로만 맞춘다.
- **구간별 맞춤(위·가운데·아래를 잇기)** — 지금은 후보 몇 개 중 고르는 방식이라 그 사이는 잇지 않는다.

## 처음에 적어 둔 방향

- **아래 기준으로도 재보기.** 두 그림의 **마지막 잉크 줄**을 바닥선으로 잡고 '바닥에서 몇 px'로 맞춘 값과,
  지금의 위 기준 값 중 더 닮은 쪽을 고른다. 요소가 그림 아래쪽 1/3에 있을 때만 켜도 된다.
- **구간별 맞춤.** 화면을 위·가운데·아래 토막으로 나눠 토막마다 밀린 값을 구하고 사이는 잇는다
  (지금은 요소 주변 한 창만 본다 — 창을 키우면 정확도가 올라갈 수 있다).
- **세로줄 무늬도 함께.** 좌우가 다른 화면(앱 가변폭)에서는 열 잉크 무늬로 x도 확인.
- **확신이 낮으면 옮기지 않는다.** 지금처럼 안내만 띄운다. 자동으로 지적을 확정하거나 핀 좌표를
  코드가 몰래 고쳐 저장하지 말 것(2번-2 · 이력 규칙).
