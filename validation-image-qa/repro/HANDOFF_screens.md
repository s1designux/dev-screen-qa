## 1. 지금 하는 일 (한 줄)
디자인 시안과 개발화면 캡처를 비교하는 검수기를 만들고 있고, 지금 조각은
**"무엇을 오류로 볼 것인가" 규칙을 늘리는 것**이다. 방식은:

> 🤖 로컬 AI가 개발화면 글자를 **읽고** → 💻 코드가 어긋난 것을 **세어** 제안 → 🙋 river님이 **승인**한 것만 규칙

AI에게 "어떤 규칙이 필요하냐"고 **묻지 않는다.** AI는 눈(글자 읽기)만 맡는다.

## 2. river님이 이 세션에 파일을 준다

Figma 검수 플러그인의 **담당자용 숨은 내보내기 버튼**(제목 3번 클릭 → `검수 자료 내보내기`)으로
뽑은 파일을 준다. 화면당 3개:

- `elements_<프레임이름>.json` — 요소 목록(이미 `run.js` 가 읽는 모양. **따로 합칠 필요 없음**)
- `design_<프레임이름>.png` — 디자인 원본
- `dev_<개발화면이름>.png` — 개발화면 캡처

받으면 **짧은 이름으로 바꿔서** `validation-image-qa/repro/` 에 둔다:

| 사례 | 짧은 이름 | 크기(디자인/개발) | 종류 |
|---|---|---|---|
| 관계사유비스 user 게시판 | `board` | 1920×1898 / 1920×1816 | PC, 세로로 긴 풀페이지·푸터·페이지네이션 |
| 관계사유비스 admin 차량위치 | `vehicle` | 360×780 / 360×780 | 모바일 웹, 하단 탭바·칩·지도 |
| 관계사유비스 admin 대시보드 | `dash` | 360×1071 / 360×1031 | 모바일 웹, 도넛 차트·카드 |
| 모두앱 출입문설정 | `door` | 184×399 / 196×436 | 앱. **글자가 읽힐 만큼 선명한지 먼저 확인** |

→ `elements_board.json`, `design_board_1920x1898.png`, `dev_board_1920x1816.png` 처럼.
(이 이름들은 `.gitignore` 에 이미 들어 있다 — 회사 화면이라 커밋하지 않는다.)

### 2-1. 첫 파일이 오면 **버튼이 제대로 만드는지부터 확인** (아직 실기 검증 안 됨)
river님께 **노선관리(`노선관리_add`) 프레임도 함께 내보내 달라고** 요청해도 좋다.
이미 다른 경로로 받아둔 정답 대조본 `elements_route.json` 이 있어서 바로 대조할 수 있다:

```bash
cd validation-image-qa/repro
python3 - <<'PY'
import json
a=json.load(open('elements_route.json')); b=json.load(open('<플러그인이 내보낸 파일>.json'))
print('칸 이름 같은가:', a['cols']==b['cols'])
print('줄 수:', len(a['rows']), len(b['rows']))
ci={c:i for i,c in enumerate(a['cols'])}
keys=['kind','x','y','w','h','text','fontSize','fontWeight','color','name','propRef','depth']
bad=sum(1 for r,s in zip(a['rows'],b['rows']) if any(r[ci[k]]!=s[ci[k]] for k in keys))
print('검수기가 읽는 값이 다른 줄:', bad, '(0이면 정상)')
PY
```
글자 줄의 `fill`·`strokeWidth` 칸은 달라도 정상이다(검수기가 글자 줄에서 안 읽는 칸이고, 플러그인 쪽이 맞다).

## 3. 화면 하나를 돌리는 순서

```bash
cd validation-image-qa/repro
./run_screen.sh board design_board_1920x1898.png dev_board_1920x1816.png
```

이게 ① 검수기(겹치기·자 재기) → ② 읽을 구역·예상 시간 보여주기 → ③ 로컬 AI 읽기(백그라운드 시작) 까지 한다.
**AI 읽기는 화면당 20~40분 걸린다.** 백그라운드로 돌려두고 기다리는 동안 다른 화면을 준비해도 된다.

읽기가 끝나면:
```bash
python3 rule_gap.py --engine board.json --read vlm_read_board.json --elements elements_board.json --out gap_board.json
```

### ⚠️ ①에서 반드시 확인할 것 — 겹치기가 맞았는가
`board.json` 의 `model` 값과 `board.align.png`(디자인을 반투명하게 겹친 그림)를 **눈으로** 본다.
**어긋나 있으면 그 화면에서 뽑는 규칙 후보는 전부 헛것이 된다.**
어긋났으면 사람이 잰 값으로 고정해 다시 돌린다(계측용):
```bash
./run_screen.sh board design_board_...png dev_board_...png <잰 ty값>
```
밀림을 재는 법: 디자인과 개발 양쪽에 다 있는 특징적인 가로 띠(예: 상단 메뉴 배경색)의 y 위치 차이를 잰다.

## 4. 이미 알고 있는 것 (다시 조사하지 말 것)

- **노선관리 화면(PC)에서 자동 겹치기가 실패한다.** 세로 밀림을 273px로 냈는데 정답은 99px(캡처 위 113px 잘라낸 뒤 기준).
  기준 요소 25개가 낸 표가 -735~+264로 흩어져 다수결이 성립하지 않았다.
  → **이 원인 찾기는 다른 세션이 맡고 있다.** (`HANDOFF_align_route.md`) 여기서는 건드리지 말고,
  겹치기가 실패하면 위 방법으로 고정해 계측만 하고 넘어간다.
- **보류 중인 규칙 제안 #1**: "표의 항목 이름은 고정으로 본다"
  (노선관리에서 항목 이름 7개가 부모 프레임 이름 `dataview` 때문에 '데이터 자리'로 접혔다.
  그중 3건이 진짜 차이였다.) river님이 **"다른 화면을 더 보고 정하자"**며 보류했다.
  → **새 화면에서 같은 패턴이 또 나오면 그때 근거를 더해 다시 올린다.**
- 관찰: 「운영 관리」→「운영관리」 띄어쓰기 오류가 체류시간·노선관리 두 화면에서 똑같이 나왔다(공통 메뉴).

## 5. 규칙을 제안할 때 (가장 중요)

**숫자 없이 승인받지 않는다.** 제안 하나마다 반드시 이걸 재서 같이 올린다:

1. **켜면 뭐가 좋아지나** — 접혀 있던 것 몇 건이 보이게 되는가, 헛지적 몇 건이 줄어드는가
2. **켜면 뭐가 사라지나** — 기존 화면에서 후보가 줄어들진 않는가 (규칙은 진짜 오류도 숨긴다)
3. **회귀** — 기존 6개 화면(체류시간·아이디찾기·로그인·표 목업·코드관리·노선관리)이 안 망가지는가
4. **체류시간 정답 8건**(`answers_stay.json`)이 접혀서 사라지지 않는가

재는 방법: `plugin-image-qa/ui.html` 을 `/tmp` 에 **복사해서** 고친 뒤 `run.js` 의 첫 인자로 그 사본을 주고 돌린다.
**원본은 승인 전에 고치지 않는다.** (`RULE_PROPOSALS.md` 의 #1 에 재현 명령이 그대로 있다.)

제안·승인·거절은 전부 `RULE_PROPOSALS.md` 에 기록한다(근거·날짜·효과 숫자·상태).
