# [새 세션용] 노선관리 화면에서 겹치기(정렬)가 실패하는 원인 찾기

## 0. 먼저 할 일
- 저장소 루트 `/Users/designgroup_02/dev-screen-qa` 의 `CLAUDE.md` 를 읽고 그 규칙을 전제로 삼는다.
- 현재 브랜치: `feat/image-qa-bottom-range`
- **작업 폴더:** `validation-image-qa/repro/`

## 1. 배경 (한 줄)
디자인 시안과 개발화면 캡처를 겹쳐 다른 곳을 찾는 검수기를 만들고 있다.
**겹치기(두 그림을 같은 자리에 포개는 것)가 틀리면 이후 지적이 전부 헛자리**가 되므로, 이게 가장 앞단이다.

## 2. 지금 문제 — 새 실제 화면에서 겹치기가 실패한다

새로 넣은 실제 회사 화면 **「노선관리」(PC, 1920×1080)** 에서:

| | 세로 밀림(ty) |
|---|---|
| 검수기가 자동으로 낸 답 | **273px** (점수 0.85, 동의한 기준 요소 2개) |
| 실제 정답 (사람이 재봄) | **-14px** (자동 실행 기준. 개발 캡처 위쪽을 113px 잘라낸 뒤 기준으로는 +99px) |

→ **287px 틀렸다.** 이후 후보 412개가 전부 헛자리다.

**정답을 어떻게 쟀나(재현 가능):** 디자인의 상단 메뉴 띠(색 `#808796`)가
디자인에서는 y 137~168, 개발 캡처에서는 y 151~182 → 세로 차이 **+14px**, 가로 차이 0.

## 3. 이미 확인된 사실 (다시 조사하지 말 것)

- 기준 요소는 **25개** 골랐고, 그중 **23개가 표를 냈다.**
- 표가 이렇게 흩어졌다 (ty 값):
  `-735, -684, -600, -396, -234, -93, -84, 54, 57, 63, 66, 264 …`
- **바른 답(-14) 근처에 표를 낸 기준 요소가 하나도 없다.** 다수결 이전에 후보 자체가 다 틀렸다.
- 2026-09-05에 커밋한 수정(`e7e695f` 기준 요소를 맨 위 5개 → 화면 전체 격자 25개)은 **이미 들어가 있다.**
  그 수정으로 체류시간 화면은 고쳐졌지만 **이 화면은 못 고친다.**
- 이 화면의 특징(원인 가설의 재료): 좌우 2단 + 표가 크고 똑같이 생긴 칸이 수백 개 +
  개발 캡처의 표 **데이터가 디자인과 완전히 다름**(디자인은 노선 6건, 개발은 2277~2291번 등 다른 데이터).
- 개발 캡처는 **실제 브라우저 스크린샷**이라 위쪽 크롬이 113px(탭+주소창+북마크바),
  디자인에 그려 넣은 가짜 크롬은 101px. 이 둘을 각각 알아보고 잘라내는 기능은 **정상 작동**했다(알림으로 알려줌).

## 4. 관련 코드 위치

- 엔진: `plugin-image-qa/ui.html`
  - `ANCHOR_COLS/ANCHOR_ROWS` (410줄 근처) — 기준 요소를 고를 격자 크기 6×6
  - `pickAnchors()` (411줄) — 기준 요소 고르기 ①중복 제외 ②짧은 글자 제외 ③격자 칸마다 하나
  - `matchAnchorPatch()` (457줄) — 기준 요소를 개발 캡처에서 찾아 밀림을 잰다(SAD 기반, `q>0.45`면 표 인정)
  - 그 아래 투표 집계 — `tol=Math.max(8,4*half)` 안에 모인 표를 무리로 묶고,
    `weight = 무리 크기 + (가로 밀림이 tol 이하면 +1.5)` 가 가장 큰 무리가 이긴다
- 재현 하네스: `validation-image-qa/repro/run.js`
  - `ANCHOR_MODE=spread`, `ANCHOR_COLS`, `ANCHOR_ROWS` 로 기준 요소 고르기를 실험할 수 있다
  - `FORCE_TX` / `FORCE_TY` 로 정렬을 고정할 수 있다(**계측용. 운영 방안 아님**)

## 5. 재현 명령

```bash
cd /Users/designgroup_02/dev-screen-qa/validation-image-qa/repro

# 자동(실패하는 현재 상태)
ELEMENTS_JSON=elements_route.json DESIGN_PNG=design_route_1920x1080.png \
DEV_PNG=dev_route_1920x1080.png DESIGN_MAX=4096 \
node run.js ../../plugin-image-qa/ui.html route

# 정답 정렬을 고정했을 때(비교 기준)
FORCE_TX=0 FORCE_TY=99 ELEMENTS_JSON=elements_route.json DESIGN_PNG=design_route_1920x1080.png \
DEV_PNG=dev_route_1920x1080.png DESIGN_MAX=4096 \
node run.js ../../plugin-image-qa/ui.html route-f99
```

결과 JSON의 `model`(겹치기 값), `anchorVotes`(기준 요소들이 낸 표), `anchorList`(고른 기준 요소),
`route.align.png`(디자인을 반투명하게 겹친 그림 — **눈으로 맞았는지 보는 데 이게 제일 빠름**)를 본다.

## 6. 해야 할 일

1. **기준 요소들이 왜 전부 틀린 자리에 붙었는지** 밝힌다.
   `anchorList`의 25개가 각각 무엇이고, 개발 캡처의 어디에 붙었는지 그림으로 확인할 것.
   (가설 예: 표 칸·입력창처럼 테두리만 있는 네모라 어디에나 맞는다 / 데이터가 달라 글자가 안 맞는다 /
   `q>0.45` 문턱이 너무 낮아 엉터리 매칭도 표를 던진다)
2. 밝혀진 원인에 대한 **고침 후보를 2~3개** 만들고, 각각을 켰을 때 결과를 **숫자로** 비교한다.
3. 고칠 때는 **`plugin-image-qa/ui.html` 본체**를 고친다(재현 하네스만 고치면 의미 없음).
