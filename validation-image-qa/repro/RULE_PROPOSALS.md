# 검수 규칙 제안 대기 목록

로컬 AI가 화면을 읽고 → **코드가 어긋난 것을 세어** 제안하고 → river님이 승인한 것만 규칙이 된다.
AI에게 "어떤 규칙이 필요하냐"고 묻지 않는다. 세는 것은 코드, 정하는 것은 사람.

상태: `제안` → `보류` / `승인`(규칙 반영) / `거절`(사유 기록, 다시 제안하지 않음)

## #1 표의 항목 이름(라벨)은 고정으로 본다

| | |
|---|---|
| **상태** | **보류** (2026-09-08, river) — "다른 화면을 더 보고 정하자" |
| 처음 제안 | 2026-09-08 |
| 근거 화면 | 노선관리_add (실제 회사 화면, PC 1920×1080) — **1개** |

**문제:** 표의 항목 이름 7개가 '데이터가 들어가는 자리'로 잘못 분류돼 사람 눈에 안 보인다.
> 노선명 · 노선 구분 · 운영 상태 · 출발지 · 노선 번호 · 노선 경로 · 운행거리 구분

**원인:** 이 항목들을 담은 피그마 프레임 이름이 `dataview`. 정책의 '컴포넌트 역할 이름' 규칙이
이름에 `data`가 들어가면 데이터 자리로 본다(`ROLE_VAR_RE`). 요소 자신의 이름은 `항목`인데,
`항목`이 고정 낱말 목록(`ROLE_FIXED_RE`)에 없어서 부모 이름에 밀린다.

**접혀서 안 보인 것 중 진짜 차이 3건 (로컬 AI가 개발 캡처에서 읽어 확인):**

| 디자인 | 개발화면 | 종류 |
|---|---|---|
| 노선 구분 | 노선구분 | 띄어쓰기 빠짐 |
| 운행거리 구분 | 운행거리구분 | 띄어쓰기 빠짐 |
| 운영 상태 | 노선 상태 | 글자가 바뀜 |

**고치는 방법:** `plugin-image-qa/ui.html`의 `ROLE_FIXED_RE` 맨 앞에 `항목|` 한 낱말 추가.
(요소 자신의 이름이 부모 이름보다 먼저 판정되므로 이 한 줄이면 된다.)

**켰을 때 효과 (계측 완료 — 원본은 안 건드리고 사본으로 측정):**

| 화면 | 지금 (후보/접힘/볼것) | 규칙 넣으면 | 결과 |
|---|---|---|---|
| 노선관리 | 448 / 222 / 226 | 448 / 215 / 233 | 숨어 있던 **7건이 보임** |

| 코드관리 | 3 / 0 / 3 | 3 / 0 / 3 | 변화 없음 |

체류시간 **정답 8건**: 지금도, 규칙을 넣어도 **접혀서 사라지는 것 0건**.

**보류 사유:** 근거 화면이 1개뿐. 나머지 4개 화면(게시판·차량위치·대시보드·모두앱)에서

## #2 (관찰 — 아직 제안 아님) 같은 띄어쓰기 오류가 두 화면에서 반복

「운영 관리」→「운영관리」가 **체류시간**과 **노선관리** 두 화면의 상단 메뉴에서 똑같이 나왔다.
공통 메뉴라서 개발 쪽에서 한 번 잘못 넣으면 모든 화면에 퍼진다.

이건 '규칙'이라기보다 **개발 쪽 실제 오류**다. 다만 규칙 후보로는
"띄어쓰기만 다른 것은 가변 판정보다 먼저 지적으로 올린다"가 될 수 있다.
아직 효과를 재지 않았다 → **숫자 없이 올리지 않는다.**

## #2 (관찰 갱신 2026-09-08) 띄어쓰기 오류 — 실재하지만 **AI 읽기로는 못 믿는다**

로컬 AI가 새 화면 4개에서 띄어쓰기 차이 3건을 냈다. **개발 캡처를 직접 잘라 눈으로 확인**한 결과:

| 화면 | AI가 낸 것 | 실제 | 판정 |
|---|---|---|---|
| 게시판 | 「내 정보」→「내정보」 | 개발도 「내정보」 | ✅ **진짜 오류** |
| 게시판 | 「내 글보기」→「내글보기」 | 개발은 「내 글보기」(띄어져 있음) | ❌ AI 오독 |
| 대시보드 | 「전체 운행 현황」→「전체운행현황」 | 개발은 띄어져 있음 | ❌ AI 오독 |

즉 띄어쓰기 오류는 **실제로 존재하지만**(내정보 · 앞선 화면들의 「운영 관리」→「운영관리」),
**AI 읽기의 띄어쓰기 판독은 3건 중 1건만 맞았다.** 이 상태로는 "띄어쓰기만 다르면 먼저 올린다"는
규칙의 효과를 잴 근거가 못 된다. **숫자 없이 올리지 않는다** → 제안하지 않고 관찰로만 남긴다.
다음에 다룬다면 AI가 아니라 **검수기 쪽에서 글자 폭·글자 수로 재는 방법**을 먼저 만들어야 한다.

## #5 감싼 상자가 이미 같은 지적을 받았으면 안쪽 껍데기는 접는다 (크기·모양)
