# 조각 제안 — 짧은 글자 바뀜을 놓치는 자리 (글자 비교 감도)

작성 2026-09-14. 착수 전 범위 확인 필요(CLAUDE.md 4번 가드레일 · 12번 stop-and-report).

## 1. 무엇이 새는가 (재현으로 확인함)

표 목업(`elements_table.json` / `design_table_1200x700.png` / `dev_table_1200x700.png`)에는
일부러 심은 진짜 오류가 3개다. 2026-09-14 실행 결과 **2개는 잡고 1개를 놓친다.**

| 심은 오류 | 지금 |
|---|---|
| 버튼 문구 `조회` → `상세 조회하기` | 잡음 (#3, conf 67) |
| 요약 글자색 파랑 → 빨강 | 잡음 (#2, conf 88) |
| 컬럼 제목 `연락처` → `담당자 휴대전화번호` | **못 잡음** |

## 2. 왜 새는가 (원인 두 가지, 숫자로 확인함)

디버그 `units`의 `h0t1`(연락처):
`mismatch 0.02 · ncc 0.80 · exact 0.26` → `textCandidateFor`의
`same = mismatch<=.3 && ncc>=.6 && exact<=.42` 를 모두 통과해 **후보를 내지 않고 빠진다.**

- **(원인 A) 상자 밖을 안 본다.** 디자인 `연락처`의 글자 상자는 폭 47.5px(3자)뿐이다.
  개발 캡처의 `담당자 휴대전화번호`는 11자라 상자를 한참 넘어가는데, 비교는 **디자인 상자 안에서만** 한다.
  상자 안 3자리는 촘촘한 한글끼리 겹쳐 `mismatch`가 0.02까지 떨어진다.
- **(원인 B) 짧은 글자에서 문턱이 헐겁다.** 안 바뀐 컬럼 제목들은 `ncc 1.00`인데
  바뀐 것만 `0.80`이다. 차이는 분명히 있으나 `ncc>=.6` 문턱을 못 넘는다.
  문턱이 헐거운 이유는 실촬영에서 **글꼴 폴백**으로 ncc가 흔들리기 때문이다(그래서 일괄 상향은 금지).

## 3. 방안 (세 걸음, 앞의 걸음만으로 목표에 닿으면 뒤는 접는다)

### 걸음 1 — 상자 밖으로 이어진 잉크 재기 (권장 · 위험 낮음)
`textCandidateFor`에서 `same` 판정으로 빠져나가기 **전에** 개발 캡처 쪽 잉크 폭을 잰다.
이미 있는 `growInkBox`(좌우로 잉크가 이어지는 만큼 상자를 넓히는 함수)를 재사용한다.
- 디자인 잉크 폭 대비 캡처 잉크 폭이 **1.35배 이상**(또는 0.7배 이하)이면
  `LABEL_TEXT_CONTENT` 후보를 낸다. 사유에 "디자인보다 글자가 길어 보입니다"를 적는다.
- 좌우 정렬(가운데·오른쪽 맞춤)로 늘어난 경우를 구분하려면 **양쪽 끝을 따로** 재고,
  한쪽만 늘었는지 양쪽인지 사유에 적는다.
- **막이(가드):** 옆 요소의 글자가 붙어 들어오면 오탐이 된다.
  `parentInnerBox`(부모 칸 안쪽)를 넘어서면 세지 않는다 — 이미 `growInkBox`가 쓰는 한계선.

### 걸음 2 — '고정 글자'에만 문턱 조이기
정책이 **고정**으로 본 글자(컬럼 제목·메뉴 이름·버튼 문구)에 한해
짧은 글자(≤6자)일 때 `ncc` 문턱을 `.6` → `.88`로 올린다. 가변 글자·긴 문장은 그대로 둔다.
- 근거: 고정 글자는 데이터로 바뀌지 않으므로 차이가 보이면 대개 진짜다.
- 신뢰도는 낮게(55~65) 매겨 사람이 먼저 보게 한다. **자동 확정 금지**(CLAUDE.md 2-2).

### 걸음 3 — (걸음 1·2로 모자랄 때만) 글자 수 세기
잉크 덩어리(세로 빈칸으로 끊은 토막) 개수를 디자인 글자 수와 견준다.
한글은 글자마다 거의 한 덩어리라 쓸 만하다. 다만 자간이 좁으면 붙으므로 **참고값**으로만 쓴다.

## 4. 끝났다고 보는 기준 (하나라도 못 넘으면 되돌린다)

1. 표 목업의 심은 오류 **3/3** 을 잡는다.
2. 체류시간 화면 정답 **7/7** 유지, 사람이 볼 후보 수가 **늘지 않는다**.
3. 웹 화면 5개 회귀에서 헛지적 총수가 **늘지 않는다**(`node run.js` 기존 세트).
4. 우비스 버스 로그인 4쪽에서 헛지적 수가 **늘지 않는다**.
5. 엔진 자체검사 전부 통과 + 걸음마다 자체검사 1줄 추가.

## 5. 하지 않을 것

- 글자를 문자로 읽기(OCR·로컬 AI)를 배포 엔진에 넣지 않는다. 로컬 AI는 **규칙을 찾는 도구**일 뿐이다(2026-09-07 확정).
- 문턱을 화면별로 사람이 매번 맞추게 만들지 않는다. 정책 층(고정/가변)에 흡수한다.
- 후보를 자동으로 오류 확정하지 않는다.
