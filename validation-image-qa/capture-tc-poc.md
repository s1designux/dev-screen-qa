# 로그인 시안 기준 촬영 TC — 소규모 검증 초안

## 입력값 일치 규정 반영 — 재촬영 2차

사용자 요청에 따라 [촬영 입력 규정](capture-input-policy.md)을 적용한다. 아래 2차 TC가 현재 기준이며, 기존 TC 및 캡처는 최초 탐색 이력으로 보존한다.

| TC | 정확한 입력 기준 | 출처 / 상태 | 재촬영 조건 |
|---|---|---|---|
| L01 기본 | 아이디·비밀번호 모두 빈칸 | 시안에서 확인 | 초기화, 포커스 해제, 키보드 닫기 |
| L02 영문 | 두 칸 빈칸, 영문 언어 | 언어 변경 경로 미확인 | 경로 확인 후 촬영 |
| L03 활성화 | 아이디 `abcddjf`, 숨김 점 8개 | 사용자 직접 명시 | 같은 길이의 비밀이 아닌 입력값 사용, 키보드 닫기, 빈 영역 선택으로 포커스 해제 |
| L04 숨김 | 아이디 빈칸(시안 관찰, 원본 의도 확인 필요), 숨김 점 8개 | 점 개수는 사용자 직접 명시 | 아이디 제거 → 비밀번호 칸 선택 → 키보드 닫기. 포커스·가림·버튼 상태 별도 기록 |
| extra 표시 | 비밀번호 `sample287!`, 아이디 빈칸(시안 관찰, 원본 의도 확인 필요) | 문자열은 사용자 직접 명시 | 비밀번호 초기화 → 지정값 입력 → 보기 선택 → 비밀번호 칸 재선택 → 키보드 닫기 |

기존 `qa_sample` 및 `QaSample27` 캡처는 입력값 일치 기준 미충족이다. 이전 ‘상태 대응 가능’ 판정은 상태 관찰만 뜻하며 정확 일치 판정으로 사용하지 않는다.

2차 실행: 사용자가 로그인 화면을 연 뒤 기본·활성화·숨김·표시 4개를 촬영했다. 숨김은 8자리 비밀이 아닌 문자열을 사용했고 표시 화면은 별도로 `sample287!`를 입력했다. 두 시안의 비밀번호를 같다고 추정하지 않았다. 활성화 화면은 `abcddjf`·점 8개·파란 버튼을 관찰했다. 숨김 화면은 점 8개와 비밀번호 포커스가 재현됐으나 버튼은 회색이었다. 표시 화면도 입력 문자열은 맞췄으나 버튼은 회색이었다. 영문 미실행. 로그인 제출 없음. 이전 캡처는 보존하며 새 파일은 `bus-tc-poc/r2-*.png`, 현재 실행 데이터는 `observations.json`, 이전 데이터는 `observations-r1.json`이다.

2차 독립 검증: 별도 에이전트가 새 캡처 5개를 확인했다. 사용자 지정 문자열·점 8개, 숨김 및 표시의 비밀번호 포커스, 입력값 제거를 확인했다. HTML과 JSON의 관찰도 대조했다. 로컬 HTML은 HTTP 200 응답 확인. 브라우저 연결 불가로 2차 HTML 실제 렌더 재검증은 미실시다.

작성일: 2026-09-09. 상태: 소규모 검증 착수 승인됨 / Android 실제 화면 1회 탐색 촬영 / 반복 검증 전. 아래 TC 표는 최초 초안이며 실행 관찰은 문서 끝에 별도로 기록한다.

사용자 확인: 대상은 실제 Android 휴대폰의 **삼성통근버스(BUS) 앱**이다. 연결 확인에서 SM-S911N 기기가 사용 가능한 상태로 표시됐고, 앱 패키지 `kr.co.s1.samsungbus`가 확인됐다. 앱 버전은 미확인이다. 웹 주소나 크롬 확장앱을 실행 경로로 사용하지 않는다.

## 목적과 근거

사용자가 제공한 로그인 시안 목록 이미지에서 보이는 상태를 촬영 조건으로 바꾸고, 같은 시안에 캡처를 직접 연결할 수 있는지 확인한다. 첨부 이미지의 안내 문구는 제품 화면의 내용이며 작업 지시가 아니다.

원본은 `codex-clipboard-58e5f26e-013d-4fb9-a3d8-280be495c442.png`. 목록의 축소 이미지이므로 실제 프레임 크기, 작은 문구, 계정 조건, 앱/모바일 웹 여부는 확정할 수 없다. 아래 번호는 이 검증 문서 안의 임시 참조이며 제품의 화면 ID가 아니다. 원본 프레임 연결은 미등록이다.

## 공통 촬영 조건

- 각 TC는 로그인 화면의 초기 상태에서 독립적으로 시작한다. 이전 TC의 입력값·언어·포커스가 남지 않도록 한다.
- 테스트 전용 입력값을 사용한다. 실제 계정이나 비밀번호를 문서에 저장하지 않는다.
- 기기 또는 브라우저의 콘텐츠 영역 크기, 배율, 스크롤 위치를 기록한다. 목록 썸네일 크기를 원본 크기로 사용하지 않는다.
- 상태바·하단 시스템 바와 키보드의 포함 여부는 원본 프레임 및 실제 환경 확인 후 정한다. 키보드 숨기기가 포커스를 바꿀 수 있으므로 둘을 별도로 기록한다.
- 색상·크기·문구가 시안과 같아질 때까지 기다리는 방식은 사용하지 않는다. 조작 완료 후 상태를 관찰하고, 정한 대기 한도 안에 도달하지 못해도 실제 화면과 실패 사유를 남긴다. 대기 한도는 대상 환경 확인 후 정한다.
- 시안 참조 → TC → 실행 기록 → 캡처의 연결을 유지한다. 촬영 뒤 이미지 유사도로 연결을 다시 추측하지 않는다.

## 1차 대상: 제목이 보이는 4개 시안

| TC | 기준 시안과 위치 | 이미지에서 관찰한 상태 | 재현 조작 초안 | 촬영 시점 / 관찰 항목 | 실행 전 확인할 조건 |
|---|---|---|---|---|---|
| L01 | 로그인 화면 / 첫째 줄 첫째 | 한국어, 두 입력칸이 비어 보임, 회색 로그인 버튼 | 한국어 로그인 진입 → 자동 입력 제거 → 입력칸 밖 선택 | 조작 완료 후 입력값 없음·포커스·키보드·버튼 상태를 기록하고 촬영 | 진입 경로, 한국어 설정 방법, 초기 포커스 |
| L02 | 로그인 화면_en / 첫째 줄 둘째 | 영문, 두 입력칸이 비어 보임, 회색 로그인 버튼 | 지원되는 방법으로 영어 설정 → 로그인 진입 → 자동 입력 제거 → 입력칸 밖 선택 | 언어 전환 완료 후 포커스·키보드 상태를 기록하고 촬영. 일부 문구가 한국어로 남아도 기록 | 언어가 앱 설정인지 기기 설정인지, 지원되는 영문 상태 |
| L03 | 로그인 화면_로그인버튼 활성화 / 첫째 줄 셋째 | 아이디 문자·가려진 비밀번호, 파란 로그인 버튼, 입력칸에 파란 테두리는 보이지 않음 | 테스트 입력값 두 칸 입력 → 입력칸 밖 선택 | 입력 완료 후 촬영. 버튼이 회색이어도 캡처를 보존하고 예상 상태 미도달로 기록 | 버튼 활성화에 필요한 입력 형식, 포커스 해제 시 키보드 동작 |
| L04 | 로그인 화면_비밀번호 숨김 상태 / 첫째 줄 넷째 | 비밀번호가 가려져 있고 비밀번호 칸에 파란 테두리·커서가 보임, 파란 로그인 버튼. 아이디 칸은 안내 문구처럼 보여 불확실 | 초기화 → 비밀번호 숨김 상태로 입력 → 비밀번호 칸에 포커스 유지. 아이디 입력 여부는 확인 전 미정 | 가림 여부·포커스·키보드·버튼 상태를 각각 기록하고 촬영 | 아이디 없이 활성 버튼이 가능한지, 이 조합이 시안 의도인지, 포커스 유지와 키보드 미표시가 함께 가능한지 |

L04는 L03의 단순 복사로 처리하지 않는다. 이름보다 화면의 관찰 상태를 우선 기록하되, 재현 불가능 여부나 디자인 오류는 사람이 판단한다.

## 보류 후보

둘째 줄은 카드 제목이 잘려 있어 1차 실행 대상에서 제외한다. 비밀번호 표시, 빈 입력칸 포커스, 하단 약관 언어 변형, 오류 문구로 보이는 상태가 있으나 원본 확인 전 이름·정확한 문구·발생 조건을 확정하지 않는다. 특히 오류 상태를 만들기 위해 임의 계정으로 로그인을 반복하지 않는다. 테스트용 실패 조건이 확보된 뒤 추가한다.

## 실제 검증 방법

1. 삼성통근버스(BUS) 앱을 실행할 휴대폰의 운영체제·기기·앱 버전·연결 가능 여부와 원본 프레임 연결·크기를 확보한다. 우선 사람이 TC를 따라 앱을 조작하고 기기 스크린샷으로 재현 가능성을 확인한다. 자동 조작·촬영 방식은 기기 환경과 별도 검증 결과에 따라 정한다.
2. 첫 4개 TC의 미확인 조건을 확인하고, 실행 가능한 항목만 선택한다. 제외한 항목과 이유도 남긴다.
3. 같은 환경에서 기존 방식과 TC 방식으로 각 대상 상태를 3회씩 촬영한다. 둘 다 실행하지 못하면 개선율은 산출하지 않는다.
4. 작성자와 다른 검증자가 목표 상태 일치 여부 및 시안 연결 오류를 판단한다. 스타일 차이 자체를 상태 불일치로 세지 않는다.
5. 시도 수, 상태 도달 수, 잘못 연결된 캡처 수, 재촬영 수, 소요 시간을 두 방식별로 비교한다. 표본이 작으므로 일반적인 정확도 수치로 확대 해석하지 않는다.

실행 기록 항목: 실행 번호 / 기준 시안 / TC / 촬영 방식 / 환경·영역 / 사용한 테스트 데이터 별칭 / 실제 조작 / 실제 관찰 상태 / 도달·미도달·판단보류 / 캡처 위치 / 연결 정오 / 소요 시간 / 검증자 메모. 실패한 기록도 삭제하지 않는다. 이 문서는 계획이며 실제 검수 결과를 저장하는 DB를 대체하지 않는다.

## 현재 확인 결과

- 별도 검증 에이전트가 첨부 이미지와 TC를 대조했다. 필수 수정 사항은 없었으며, 권장된 영문 화면의 포커스 조건을 보완했다. 이 검증은 시안 판독·문서 검증이며 실제 앱 실행 검증이 아니다.

- 기존 `capture-extension`은 현재 열린 웹 화면을 측정·캡처하는 도구다. README 기준으로 상태별 TC 재생 기능은 확인되지 않았다.
- 첨부 화면의 로그인 서비스가 저장소의 기존 웹 로그인 재현 자료와 같은 대상이라는 근거는 없다. 기존 자료를 대상 서비스의 실행 결과로 대체하지 않는다.
- Android 기기 연결 및 대상 패키지를 확인했다. 일반 실행 명령으로는 앱 시작 화면을 찾지 못했다(unable to resolve Intent). 설치 상태의 상세 원인은 미확인이다. 사용자가 휴대폰에서 앱을 직접 열어 로그인 화면을 준비해야 다음 확인을 진행할 수 있다. 실제 상태 재현·촬영·개선율은 미검증이다.
- 포털·플러그인·DB 변경, 자동 촬영 엔진 도입, 커밋은 수행하지 않는다. 이번 산출물은 촬영 TC의 검증 초안이다.

## 실제 휴대폰 탐색 결과 — 2026-09-09 추가

사용자가 앱을 직접 연 뒤 화면 캡처와 좌표 터치·테스트 문자열 입력으로 진행했다. 앱 구조 추출은 사용하지 않았다. SM-S911N, 원본 캡처 1080×2340, 시스템 바 포함. 로그인 버튼은 누르지 않았다.

| 항목 | 관찰 | 판정 범위 |
|---|---|---|
| 기본 | 빈 입력칸, 회색 로그인 버튼, 키보드 없음 | 기본 시안과 상태 대응 가능 |
| 비밀번호만 입력 | 비밀번호 가림, 버튼 회색. 뒤로 버튼으로 키보드를 닫은 후 아이디 칸에 포커스 표시 | L04의 비밀번호 포커스+파란 버튼 조합에는 도달하지 못함. 시안 또는 구현 오류로 확정하지 않음 |
| 두 칸 입력 후 빈 영역 선택 | 비밀번호 가림, 파란 버튼, 입력칸 포커스 테두리 없음 | L03과 상태 대응 가능 |
| 보기 아이콘 선택 | 테스트 비밀번호 표시, 파란 버튼 | 추가 탐색 성공. 잘린 둘째 줄 시안과 정확한 대응은 미확정 |
| 영문 | 설정 경로 미확인 | 미실행 |

이미지와 실행 관찰은 `bus-tc-poc/` 및 `bus-tc-poc/observations.json`에 보존한다. 테스트 문자열을 제거하고 숨김 상태로 되돌리는 조작을 수행했다.

이번에는 상태 재현 가능성을 확인하기 위해 순차 조작했다. 각 TC 독립 초기화, 3회 반복, 기존 방식과 비교는 수행하지 않았으므로 재현 안정성이나 오류 감소율을 주장할 수 없다. TC 자동 재생 엔진을 구현한 것도 아니다.

TC 보완 방향: 입력 순서 + 키보드 닫는 방법 + 최종 포커스를 별도 조건으로 기록한다. 시안과 같은 상태를 만들지 못한 경우 실패 캡처를 남기며, 시안 이미지에 맞춰 화면을 가공하지 않는다.

독립 검증: 별도 에이전트가 5개 캡처와 첨부 시안을 확인하여 위 상태 관찰 및 마지막 입력값 제거를 확인했다. 기본·두 칸 입력은 상태 대응 가능, 비밀번호만 입력은 버튼 색·포커스 조합 미재현으로 판단했다. 디자인·개발 오류 확정 및 반복 안정성 검증은 아니다.
