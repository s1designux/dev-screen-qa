# 개발화면 검수기

여러 디자인 프레임과 여러 개발 캡처를 **Figma 캔버스의 같은 행끼리 비교**하고, 자동 정렬 뒤 다른 영역을
후보 번호로 표시하는 로컬 Figma 플러그인입니다. 외부 API와 AI 토큰을 사용하지 않습니다.

## 설치

1. Figma 데스크톱 앱 → **Plugins → Development → Import plugin from manifest…**
2. 이 폴더의 `manifest.json` 선택
3. **개발화면 검수기** 실행

## 사용 흐름

1. 디자인 원본과 개발 캡처를 한 행에 하나씩 나란히 배치합니다.
   - 왼쪽에는 디자인 원본, 오른쪽에는 개발화면 캡처본을 둡니다.
   - 한 행에는 디자인 1개와 개발 캡처 1개만 둡니다.
2. 검수할 디자인 프레임과 Figma에 이미 올린 개발화면 이미지를 모두 드래그해 선택합니다.
   - 디자인 프레임과 개발화면 이미지를 함께 선택해도 자동으로 구분합니다.
3. **검수 시작** — 선택 자료를 읽고 같은 행의 두 자료를 자동으로 찾아 정렬·겹침·차이 찾기를 실행
4. 패널 번호를 눌러 개발 캡처 위 표시와 살아 있는 디자인 레이어를 함께 포인팅
5. 필요할 때만 **겹쳐보기**로 사람이 추가 확인
6. 번호를 **오류 확정 / 제외 / 보류**로 판정

## 비교 방식 (1.0 → 요소 우선 비교로 개편, 2026-09-02)

1. **원본 해상도로 읽기.** 디자인 프레임과 개발 캡처를 모두 원본 크기(최대 4096px)로 읽습니다. 24px 아이콘, 10px 푸터 글자, 1px 테두리도 비교 대상이 됩니다.
2. **구역별 정렬.** 디자인의 큰 묶음(헤더·본문·푸터 등)마다 개발 캡처에서 자기 자리를 따로 찾습니다. 전체를 한 가지 오프셋으로 맞추지 않으므로 푸터가 헤더와 다르게 밀려 있어도 됩니다.
3. **디자인 전용 장식 제외.** 화면 위·아래 끝에 붙어 있고 개발 캡처에 짝이 없는 큰 영역(가짜 브라우저 탭바 등)은 후보에서 빼고 패널 상단에 안내만 남깁니다.
4. **요소 우선 비교.** Figma 요소(글자·아이콘·테두리나 배경이 있는 도형)마다 그 자리를 비교해 누락 / 위치 이동 / 글자 내용·모양·색 / 아이콘 / 모양·크기 후보를 만듭니다. 요소 검사에서 "같다"고 본 자리는 픽셀 비교가 다시 후보를 만들지 않습니다.
5. **빈자리 픽셀 비교.** 요소가 없는 곳만 픽셀 블록으로 비교해 개발에만 있는 요소 등을 찾습니다.
6. **글자 후보는 독립.** 글자 차이는 다른 후보에 흡수되지 않고 항상 자기 번호를 가지며, 패널에 디자인 원문("디자인 글자: …")을 함께 보여 사람이 대조할 수 있게 합니다. 긴 글자줄은 토막 내어 일부만 바뀐 자리를 짚습니다.

## 캔버스에 표시되는 것

- 개발 캡처 원본 비율을 유지한 프레임
- 검토 후보 번호와 틀린 영역 사각형
- 후보 분류 라벨: 요소 추가·누락, 위치·정렬·크기, 색상·모양, 아이콘·이미지, 글자 내용·모양·영역 차이
- 컴포넌트 사이 간격 차이: 두 컴포넌트 테두리와 빈 공간의 색상 띠·측정선
- 겹쳐보기: 검수 결과 프레임 위에 디자인 이미지를 반투명으로 얹어 그 자리에서 확인

개발 캡처만 보고 개발 쪽의 정확한 px 값을 추측하지 않습니다(위치 이동·간격은 "약 Npx"). 자동 결과는 전부 후보이며,
사용자가 **오류 확정**한 번호만 오류로 취급합니다.

## 한계

- 비교할 자료는 캔버스의 같은 행을 기준으로 찾습니다. 한쪽이 빠지거나 같은 종류가 두 개 이상인 행은 먼저 배치를 고쳐야 합니다.
- 글자 판독(OCR)은 하지 않습니다. 글자 차이는 모양·밝기 패턴으로만 판단하므로 **10px 안팎 작은 글자에서 몇 글자만 바뀐 것**(예: 대표이사 이름)은 "글자 수나 띄어쓰기가 달라 보임" 정도로만 잡히거나 놓칠 수 있습니다. 디자인 원문을 보고 눈으로 대조해 주세요.
- 개발 캡처의 글꼴이 디자인과 다르면(폴백 글꼴 등) 글자 후보가 늘어납니다. 이때는 "폰트 모양" 또는 "글자 내용" 라벨로 나옵니다.
- 한 구역 안에서 왼쪽 묶음과 오른쪽 묶음이 서로 다른 방향으로 밀린 경우(헤더 로고는 오른쪽으로, 유틸리티는 왼쪽으로) 한쪽이 누락·추가로 나올 수 있습니다.
- 캡처 속 동적 데이터, 애니메이션, 글자 렌더링 차이는 후보를 늘릴 수 있습니다.
- 컴포넌트 안의 안쪽여백은 간격 후보에서 제외합니다. 컴포넌트 경계가 분명하지 않으면 간격 후보를 만들지 않을 수 있습니다.
- 긴 이미지는 Figma 이미지 제한에 맞춰 표시용 사본만 축소합니다. 비교 좌표는 원본 기준으로 계산합니다.
- Figma 캔버스 이미지는 보이는 자르기·비율을 포함해 PNG로 읽습니다. 이미지 채움이 없는 일반 도형이나 내부 요소가 있는 디자인 프레임은 개발 캡처로 오인하지 않습니다.
- 포털 SQLite 동기화는 아직 하지 않습니다. 포털이 원본이라는 프로젝트 원칙은 그대로 유지합니다.
- Figma 실제 실행 검증은 데스크톱 앱에서 별도로 확인해야 합니다.

## 검증

```bash
npm run test:image
```

영역 묶기, 원본 좌표 복원, 디자인 기준값, 글자 차이 분류, 가로·세로 컴포넌트 간격, 안쪽여백 제외 등을 로컬 Chrome에서 확인합니다.

실제 화면 재현(아이디 찾기 · 로그인): `validation-image-qa/repro/README.md` 참고. 디자인 export PNG + 개발 캡처 + Figma 요소 목록으로
플러그인 엔진을 헤드리스 Chrome에서 그대로 돌려 후보 목록과 번호 오버레이 PNG를 만듭니다.
