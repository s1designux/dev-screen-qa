# 개발화면 검수기

여러 디자인 프레임과 여러 개발 캡처를 **Figma 캔버스의 같은 행끼리 비교**하고, 자동 정렬 뒤 다른 영역을
후보 번호로 표시하는 로컬 Figma 플러그인입니다. 외부 API와 AI 토큰을 사용하지 않습니다.

## 설치

1. Figma 데스크톱 앱 → **Plugins → Development → Import plugin from manifest…**
2. 이 폴더의 `manifest.json` 선택
3. **개발화면 검수기** 실행

## 사용 흐름

1. 디자인 원본과 개발 캡처를 한 행에 하나씩 나란히 배치합니다.
   - 왼쪽에는 디자인 원본, 오른쪽에는 개발화면 캡처본을 둡니다.
   - 한 행에는 디자인 1개와 개발 캡처 1개만 둡니다.
2. 검수할 디자인 프레임과 Figma에 이미 올린 개발화면 이미지를 모두 드래그해 선택합니다.
   - 디자인 프레임과 개발화면 이미지를 함께 선택해도 자동으로 구분합니다.
3. **검수 시작** — 선택 자료를 읽고 같은 행의 두 자료를 자동으로 찾아 정렬·겹침·차이 찾기를 실행
4. 패널 번호를 눌러 개발 캡처 위 표시와 살아 있는 디자인 레이어를 함께 포인팅
5. 필요할 때만 **겹쳐보기**로 사람이 추가 확인
6. 번호를 **오류 확정 / 제외 / 보류**로 판정

## 캔버스에 표시되는 것

- 개발 캡처 원본 비율을 유지한 프레임
- 검토 후보 번호와 틀린 영역 사각형
- 후보 분류 라벨: 요소 추가·누락, 위치·정렬·크기, 색상·모양, 아이콘·이미지, 글자 모양·영역 차이
- 컴포넌트 사이 간격 차이: 두 컴포넌트 테두리와 빈 공간의 색상 띠·측정선
- 겹쳐보기: 검수 결과 프레임 위에 디자인 이미지를 반투명으로 얹어 그 자리에서 확인

개발 캡처만 보고 개발 쪽의 정확한 px 값을 추측하지 않습니다. 자동 결과는 전부 후보이며,
사용자가 **오류 확정**한 번호만 오류로 취급합니다.

## 1.0 한계

- 비교할 자료는 캔버스의 같은 행을 기준으로 찾습니다. 한쪽이 빠지거나 같은 종류가 두 개 이상인 행은 먼저 배치를 고쳐야 합니다.
- 캡처 속 동적 데이터, 애니메이션, 글자 렌더링 차이는 후보를 늘릴 수 있습니다.
- 푸터·하단 묶음이 통째로 조금 밀린 경우, 연쇄 오탐은 줄이되 앞 컴포넌트와의 간격 변화는 별도 후보로 남깁니다.
- 같은 요소가 다른 위치에서 다시 발견되면 누락·추가로 중복 표시하지 않고, 먼저 간격 변화 또는 위치·정렬 차이 후보로 분류합니다.
- 컴포넌트 안의 안쪽여백은 간격 후보에서 제외합니다. 컴포넌트 경계가 분명하지 않으면 간격 후보를 만들지 않을 수 있습니다.
- 긴 이미지는 Figma 이미지 제한에 맞춰 표시용 사본만 축소합니다. 비교 좌표는 원본 기준으로 계산합니다.
- Figma 캔버스 이미지는 보이는 자르기·비율을 포함해 PNG로 읽습니다. 이미지 채움이 없는 일반 도형이나 내부 요소가 있는 디자인 프레임은 개발 캡처로 오인하지 않습니다.
- 포털 SQLite 동기화는 아직 하지 않습니다. 포털이 원본이라는 프로젝트 원칙은 그대로 유지합니다.
- Figma 실제 실행 검증은 데스크톱 앱에서 별도로 확인해야 합니다.

## 검증

```bash
npm run test:image
```

영역 묶기, 원본 좌표 복원, 디자인 기준값, 색상·글자 차이, 가로·세로 컴포넌트 간격, 안쪽여백 제외를 로컬 Chrome에서 확인합니다.
