## 다음 조각이 하는 일

**개발 값 ↔ 시안 값을 짝지어 다른 곳을 찾아내는 것.** 세 걸음이다.

1. **짝 맞추기** — 시안 요소와 개발 요소를 이름표 없이 잇는다(자리·크기·글자로).
   이미 검증된 길이 있다: `validation-auto/`(17/17) · `plugin-value-qa/code.js`.
2. **값 견주기** — 글꼴·글자크기·굵기·색·모서리·테두리·크기·자리를 견준다.
   무엇을 보고 무엇을 넘길지는 이미 있는 **검수 규칙 4계층**(CLAUDE.md 8번)을 그대로 쓴다.
3. **후보로 올리기** — 다른 곳을 `auto_candidate` 에 넣는다. **지적이 아니라 후보다.**
   사람이 '지적 등록'을 눌러야 `inspection_issue` 가 생긴다(CLAUDE.md 2번-2).

## 지켜야 할 것

- 자동으로 **확정하지 않는다.** 신뢰도와 함께 후보만 만든다.
- 그림 비교(픽셀)로 가지 않는다. 웹은 **값**으로 본다. 그림은 사람이 좌우로 볼 때만 쓴다.
- 화면마다 사람이 설정하게 만들지 않는다 — 기본값(4계층 상속)으로 흡수한다.
- 앱·PC S/W 길(그림 대조)은 건드리지 않는다.

## 정해진 것 (river 2026-09-14)

- **시안 값은 플러그인이 함께 보낸 `검수요소`로 받는다.** Figma 토큰 없이 된다. (`valueqa/design.py`)
- **검수 순서: ①시안↔개발 값 대조 → ②토큰·컴포넌트 규정 → ③흐름.**
- **화면끼리 일관성(같은 덩어리가 화면마다 같은 간격·글꼴인가)은 하지 않는다** — 시안 대조가 되면 저절로 정리된다.
- **규정의 정본은 `github.com/s1designux/S1-UX-DESIGN-with-AI`** (공개). 기계가 읽는 곳은 `registry/`
  (`tokens/*.json` · `components/*.json` · `governance/*.json` · `patterns/{id}/flow.md`) + `assets/css/tokens.css`.
  아직 정리 중이라 **시시각각 바뀐다 → 복사해 두지 말고 검수할 때마다 받아오고, 본 판(커밋)을 결과에 적는다.**
- **검수 PC는 깃허브 내려받기가 된다**(올리기만 막힘). 파일로 들여오는 통로는 필요 없다.
  단 `raw.githubusercontent.com` 이 따로 막혀 있을 수 있어, 착수 때 한 번 확인하는 절차를 둔다.

## ① 걸음 — 만든 것 (2026-09-14)

`valueqa/` — 시안 값과 개발 값을 이름표 없이 짝짓고 값을 견주어 **후보**를 뽑는다. 후보는 지적이 아니다.

```
python3 -m valueqa 시안.json 개발.값.json --지시서 수정요청.md --보기 결과.html
python3 -m valueqa.selftest
```

**결과물은 '보는 문서'가 아니라 '고치는 문서'다** (river 2026-09-14).
`--지시서` 가 기본 산출물 — 한꺼번에 고칠 것(같은 값으로 맞추는 여러 곳)을 묶어 주고,
요소별 CSS 덩어리를 개발 화면에서 읽은 태그·class 로 적어 그대로 붙여 쓰게 한다. 끝에 체크 목록.
**값부터 일괄로 바로잡게 한 뒤, 그림·배치를 눈으로 보는 검수는 최소한만** 한다.

**어느 화면의 어느 항목인지가 있어야 반영된다** (river 2026-09-14). 그래서 고칠 것마다
`{화면키}-{번호}` 를 붙이고, 화면 이름·주소·요소의 글자·화면 안 자리를 함께 적는다.

**자리는 개발 화면 기준으로 적는다** (river 2026-09-14). 디자인 레이어 이름·시안 프레임 이름은
디자이너가 임의로 붙인 것이라 개발·퍼블리싱이 못 알아본다. 그래서 `#id` 나
`section.stats > div.card` 같은 **CSS 선택자**를 앞세우고, 시안 이름은 맨 뒤에 〈시안 …〉 로만 둔다.
이를 위해 재는 자(`plugin-value-qa/collect-core.js`, **core-1.2**)가 요소의 `id` 와 선택자(`sel`)를
함께 적도록 했다. 파생물은 `node plugin-value-qa/build-tools.js` 로 다시 만든다(경로는 저장소 기준으로 고침).
옛 측정값(선택자 없음)이면 `태그.class` 로 물러난다.
화면 여러 개는 `지시서묶음()` 으로 한 문서에 담고, **화면이 달라도 같은 고침은 맨 앞에 모아 준다.**
화면키는 포털 사람키(`CV-WEB-012`)를 그대로 쓰면 된다 — 포털을 붙일 때 넘겨 주면 된다.

알고리즘은 새로 짓지 않고 이미 검증된 `plugin-value-qa/ui.html`(runMatcher·compareRows·doCompare)을
파이썬으로 옮겼다. 검수는 포털에서만 하기로 했으므로(CLAUDE.md 4번) 피그마 창 밖에서 돌아야 한다.
자가검사가 **옛 엔진과 셈이 같은지**(값다름 6·더있음 1·밀림 7·주의 2·일치 2)까지 잠가 둔다 —
`npm test`(옛 엔진)와 `python3 -m valueqa.selftest`(새 엔진)가 같은 숫자를 낸다.

옮기면서 한 가지만 바꿨다: **안쪽여백(padding)은 후보로 올리지 않는다**(퍼블리싱 소관, CLAUDE.md 8번).
값은 그대로 재서 '참고'로 남긴다.
