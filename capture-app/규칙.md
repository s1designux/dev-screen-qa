# 촬영기 규칙 모음 (지금까지 정한 것)

이 파일 한 장만 읽으면 "왜 이렇게 도는지" 알 수 있게 적는다.
설계 원칙은 저장소 뿌리의 `CLAUDE.md`, 이어받는 법은 `HANDOFF.md` 에 있다.

## 1. 흐름 — 네 걸음

① 디자인 고르기 → ② 찍을 목록 → ③ 조건 확인 → ④ 전체 촬영 → (검수로 보내기)

④ 에는 **진행 막대**가 있다 — 몇 번째를 찍는 중인지, 지금까지 몇 장을 찍고 몇 장을 못 찍었는지.
3초마다 저절로 새로 읽는다(멈춘 것인지 도는 것인지 사람이 알 수 있게).

- 브라우저에서 돈다: `./site.sh` → http://localhost:8767 (내 PC에서만)
- 찍는 일 자체는 `lib/runner.py` 가 하고, 사이트는 그 앞 준비만 맡는다.

## 1-1. PC 웹 검수는 '값 대조' 다 (2026-09-14 추가 · 시험 단계)

**PC 웹은 그림을 견주지 않는다. 값을 견준다.** 웹은 소스를 읽을 수 있으니
색·글꼴·글자크기·굵기·모서리·테두리·크기·자리를 숫자로 바로 대조한다.
그림 대조는 **모바일 앱과 설치형 소프트웨어**에만 해당한다.

- 재는 자는 새로 만들지 않는다 — 이미 검증된 `capture-extension/collect-core.js` 를 그대로 빌려 쓴다(복사본 없음).
  사람이 북마크를 눌러 한 화면씩 재던 것을, 브라우저가 화면을 여는 김에 대신 잰다.
- 한 번 열 때 **값(JSON) + 그림(PNG)** 을 함께 남긴다. 그림은 검수 화면 좌우 2단에서 사람이 볼 몫이다.

- 웹은 **폰을 꽂지 않는다.** 브라우저만 열면 되므로 **윈도우 PC에서 그대로** 돈다.
- 브라우저는 **이미 깔려 있는 크롬 → 엣지**를 빌려 쓴다(따로 내려받지 않는다).
- 이름표에 `플랫폼: web` 을 적으면 웹 길로 간다 — `apps/웹-예시.yaml` 참고.
  화면마다 `주소`, 위쪽에 `기본주소`·`화면폭`·`기다림`.
- 동작 말은 앱과 거의 같다(탭 · 있으면탭 · 입력 · 기다림 · 스크롤 · 뒤로 · 지우기 · 되풀이).
  **다른 것 하나:** 자리로 누르는 말이 앱은 `탭좌표 가로%,세로%`, 웹은 `탭칸끝 <칸 안내글>` 이다(위 1-2 참고).
- 사진은 앱과 **같은 이름 규칙**(화면ID@상태.png)과 같은 `찍은목록.json` 을 남긴다 —
  검수 포털 접수 흐름이 그대로 먹힌다.
- 세로는 **페이지 전체를 통짜로** 찍는다(스크롤해서 이어 붙이지 않는다).
- **자동 캡쳐 사이트(네 걸음)에도 붙었다(2026-09-14).** 플러그인에서 유형을 고르면 웹 길로 간다 —
  ② 앱 주소 대신 **기본 주소 + 찍을 폭**, 줄마다 **개발 주소** · ③ 폰 상태 대신 **브라우저·연장·주소**
  (다 갖춰졌으면 표 자체를 보이지 않는다) · ④ 값과 그림을 함께 남긴다.
  포털에는 웹 화면(`{서비스}-WEB-번호`)으로 들어가고, 개발 실행 키 자리에 사이트 주소가 들어간다.
- **유형은 사람이 고른다.** 플러그인 `검수 화면 보내기` 에서 PC 웹 / 모바일 웹 / 앱 / PC S/W 중 하나를
  고르기 전에는 보내기가 눌리지 않는다(짐작하지 않는다). 웹 둘은 브라우저 하나로 같은 길을 간다.
- 설치는 `설치/윈도우.md` 한 장.

### 무엇을 찍을지는 디자인이 정한다

시안에 없는 화면을 엉뚱하게 찍지 않도록, **포털이 내려준 촬영요청.json(디자인 기준 TC)** 대로만 돈다.
포털은 디자인만 알고 개발 주소는 모르므로, **주소표** 한 장을 사람이 한 번 적어 잇는다
(화면 ID ↔ 개발 route 는 원래 사람이 1회 잇는 것 — CLAUDE.md 7번).

    웹TC.bat 촬영요청.json apps\웹-주소표-예시.yaml            (윈도우)
    python3 lib/webtc.py 촬영요청.json apps/웹-주소표-예시.yaml  (맥)

결과는 포털이 알아보는 이름(`TC-<case_id>@capture.png`)과 `design-capture-results-v1` 모양으로 쌓인다.
주소표에 없는 TC는 지우지 않고 **'못한 것'에 까닭과 함께** 남긴다.

주소표 없이 목록만으로 돌리고 싶으면 `apps/웹-예시.yaml` 모양을 쓴다.

## 1-2. 매체 유형표 — 겪은 것을 쌓는다 (2026-09-14)

유형마다(PC 웹 · 모바일 웹 · 앱 · PC S/W) **원래 이런 점이 다르다**를 한 곳에 모아 둔다 — `lib/매체.py`.
코드는 그 표를 보고 움직인다. 한 번 데인 것을 그때그때 고치면 다음 사이트에서 같은 식으로 또 깨지기 때문이다.

표에 있는 것: 무엇으로 견주나(값/그림) · 찍는 손 · **찍는 중 안내말** · 주소 끝 빗금을 뗄지 ·
자리(%)로 눌러도 되는지 · 글자를 한 글자씩 칠지 · 단추가 꺼져 있을 수 있는지 · **겪은일**.

**쌓는 법:** 새로 데이면 그 유형의 `겪은일` 에 한 줄 적는다(언제 · 무슨 일 · 그래서 무엇을 하기로 했나).
그 '그래서'가 값으로 표현되면 위쪽 칸을 고친다. 지우지 않고 쌓는다.

지금까지 쌓인 것(PC 웹, 2026-09-14 · 유비스사용자포털):

| 겪은 일 | 그래서 |
|---|---|
| 기본 주소 끝 빗금을 프로그램이 떼어내 `…/busportal` 로 열었고 서버가 404 로 보냈다. 그 오류 화면을 로그인 화면인 줄 알고 찍었다 | 웹은 **주소 끝 빗금을 떼지 않는다**. 사람이 적은 대로 연다 |
| 시안(1920×1080) 기준 세로 38% 로 눈 아이콘을 눌렀는데 브라우저 창은 세로 900 이라 빈 곳을 눌렀다 | 웹은 **자리(%)로 누르지 않는다**. `탭칸끝 <칸 안내글>` — 그 칸에 겹친 작은 단추 중 이름표가 '보기·눈'인 것을 누른다 |
| 로그인 단추가 꺼져 있는데(`disabled`) 누르라고 해서 30초를 기다리다 멈췄다 | 잠깐만(8초) 기다리고 **"단추가 꺼져 있습니다"** 라고 말한다. 값은 **한 글자씩** 쳐 넣는다(자판을 뗄 때만 단추를 켜는 화면이 있다) |
| 목록을 검사하는 쪽(`lib/actions.py`)은 아는 말을 정작 찍는 쪽(`lib/webshot.py`)이 몰라 '모르는 말입니다' 로 멈췄다 | 웹 말 목록을 `actions.웹말` 한 곳에 두고 **검사와 실행이 같은 목록**을 본다 |
| 앱에서 화면 키보드를 닫으려고 쓰던 `뒤로` 를 웹 초안에도 넣었다. 웹에서 `뒤로` 는 **앞 페이지로 가는 것**이라 적어 둔 아이디·비밀번호가 지워지고 로그인 단추가 도로 꺼졌다 | PC 는 자판이 화면을 가리지 않는다 — 웹 초안에 '키보드 닫기'용 `뒤로` 를 넣지 않는다(`화면키보드: False`) |

## 2. 디자인은 Figma에서 드래그로 고른 것만 들어온다

- 캔버스에서 찍을 화면을 드래그로 감싸 고르고, 플러그인 `plugin-pick` 의 **보내기**.
- 이름 목록이 아니라 **그림**으로 확인시킨다 — 웹 시안과 앱 시안을 헷갈리지 않게.
- 폭 1400 이상이면 "폰치고 넓음" 이라고 빨갛게 짚는다.
- 플러그인이 함께 보내는 것: 그림(PNG) · 화면 안 글자 · 아이콘 이름과 자리 · **시안의 값**
  · **검수 포털 자동 검수용 요소 목록·설정**(2026-09-10, 검수기와 같은 모양) — 검수로 보낼 때 포털에 시안 판으로 함께 들어가 후보가 바로 뜬다.
  (색·글꼴·글자크기·굵기·모서리·테두리·크기·투명도).
- 그래서 이 길에서는 Figma 열쇠(토큰)가 필요 없다. 열쇠 방식(파일 주소 붙여넣기)은 예비로만 남긴다.
- **검수 화면이 이미 있는 프레임은 촬영 준비를 거치지 않는다(2026-09-10).** 플러그인이 검수 포털(8765)에
  "이 프레임, 검수 화면 있어?"를 묻고, 있으면 단추가 **검수 시안 바꾸기**로 바뀐다. 누르면 그 페이지 시안만
  새 판으로 갈아끼우고(옛 판·핀은 그대로) "검수 화면 열기" 링크가 뜬다. 처음 오는 프레임은 지금처럼 촬영 준비로.
  프레임 이름이 같은 검수 화면이 하나면 고르게 하지 않고 그 시안을 덮어쓴다(같은 이름이 여럿이면 촬영 준비로). 포털이 꺼져 있으면 이 단추는 숨는다.

## 3. 순서는 '디자인에 놓인 차례' 그대로

- 이름으로 걸러 골라도, 여러 페이지에서 골라 모아도, 번호는 캔버스 자리 순서로 다시 매긴다.
- 위 줄부터, 한 줄 안에서는 왼쪽부터. 페이지가 여럿이면 페이지 차례가 먼저다.

## 4. 사진 이름 = 포털과의 유일한 접점

`{서비스코드}-{AND|IOS|WEB}-{번호}@{상태}.png`  (예: `BUS-AND-002@비번커서.png`)

- 프로그램끼리 직접 연결하지 않는다. 폴더에 사진이 쌓이면 끝이다.

## 4-0. 검수 페이지 이름 = 디자인 프레임 이름 그대로

포털 검수 페이지에 보일 이름은 **시안 프레임 이름을 자르지 않고 통째로** 쓴다.

- 사진 파일 이름의 `@뒷토막`(상태)은 **파일 구분용일 뿐**, 페이지 이름이 아니다.
- 뒷토막만 쓰면 `long` · `default` 처럼 무슨 화면인지 알 수 없는 이름이 된다.
- 예: 프레임 `로그인 화면_비밀번호 커서 활성화 상태` → 페이지 이름도 그대로.
  프레임 `UVIS BUS_삼성통근버스_00Splash_long` → 그대로.
- 같은 화면을 다시 찍어 보냈는지도 이 **전체 이름**으로 맞춘다(지적이 없으면 그 자리를 갈아 끼움).
- 이미 들어가 있는 옛 이름은 건드리지 않는다. **다시 찍어 보낼 때부터** 새 이름이 된다.

## 4-1. '눌러 들어갈 메뉴'는 비워 둔다 (사람이 적는다)

디자인 화면 이름은 앱 안에 있는 글자가 아니다. 그래서 초안은 늘 `-` 로 둔다.

- 앱을 켜면 바로 나오는 화면(스플래시·로그인 등)은 `-` 그대로.
- 이름에 **스플래시(splash)** 가 있으면 **기다릴 시간을 적지 않는다.** 앱을 켠 순간부터
  0.5초 동안 여러 장을 찍어 두고 그중 한 장을 자동으로 고른다(7-1의 ⑥).
- 메뉴를 눌러 들어가야 하면, **앱에 실제로 보이는 글자**를 사람이 적는다.
- 디자인 이름을 그대로 누르려 하면 "그런 글자 없음"으로 그 묶음이 통째로 멈춘다.

## 5. 같은 화면의 상태 변형은 이어서 찍는다

- 화면 이름의 앞부분(뿌리)이 같으면 한 묶음 — 앱을 껐다 켜지 않고 앞 장에 이어서 찍는다.
- 촬영 도구는 **한 번만** 띄운다(대본을 미리 다 만들어 폴더째 넘긴다). 예전 방식은 한 장에 30초 가까이 걸렸다.
- 예전 방식이 필요하면 `한장씩=1 ./run.sh …`.

## 6. 동작 — 그 상태를 만드는 법

쓸 수 있는 말은 일곱 가지. 여러 개는 `→` 로 잇는다.

| 말 | 뜻 |
|---|---|
| `탭 로그인` | 그 글자를 누른다 |
| `입력 아이디=test01` | 그 칸을 눌러 **먼저 비우고** 글자를 적는다 (앱이 기억해 둔 값이 덧붙지 않게) |
| `입력 아이디=<아이디>` · `입력 비밀번호=<비번>` | 앱 정보에 적어 둔 **시험 계정**을 찍는 순간에 넣는다 |
| `입력 비밀번호=<틀린비번>` | 일부러 **틀린 비밀번호**(맨 끝 한 글자만 바꾼 것)를 넣는다 — 로그인 실패 화면용 |
| `기다림 2` | 2초 기다린다 |
| `스크롤` | 아래로 한 번 굴린다 |
| `뒤로` | 뒤로 간다(키보드도 닫힌다) |
| `지우기` | 적은 글자를 지운다 |
| `탭좌표 78,41` | 글자 없는 아이콘은 자리(가로%,세로%)로 누른다 |
| `되풀이 5` | 그 뒤에 오는 것들을 5번 되풀이한다 (예: 로그인 5번 실패) |
| `있으면탭 취소` | 있으면 누르고 없으면 지나간다 (삼성패스 저장 팝업처럼 끼어드는 것) |

- **동작이 비면 앞 장과 똑같은 사진이 찍힌다.** ②에서 빨갛게 표시하고 저장할 때 한 번 잡는다.
  일부러 같은 화면을 두 번 찍는 것이면 '그대로 진행'.
- 비밀번호는 이름표·코드에 적지 않는다. 동작에는 `<아이디>` · `<비번>` 표식만 적는다.
  진짜 시험 계정은 촬영 준비 사이트 ② **앱 정보**의 '시험 아이디 · 시험 비밀번호' 칸에 한 번만 적는다.
  그 값은 이 컴퓨터의 `apps/앱사전.json`(깃 제외)에만 남고, 찍기 직전에 표식 자리에 들어간다.
  검수용 시험 계정만 적는다 — 진짜 개인 계정은 적지 않는다.

## 7. 동작 초안은 자동으로 채워진다 (`site/동작규칙.py` 한 곳)

화면 이름 뒷토막 + 시안 속 글자·아이콘 자리를 보고 짓는다. 지어낸 것은 초안이고 확정은 사람이 한다.

| 이름 뒷토막 | 짓는 동작 |
|---|---|
| 커서 · 포커스 · 선택 시 | `탭 <그 칸의 안내 글자>` |
| 로그인 시도 · 유효하지 않은 · 실패 | `<아이디>`와 **`<틀린비번>`** 채우고 `탭 로그인 → 기다림 3` — 맞는 비밀번호를 넣으면 로그인이 되어 오류 화면을 못 찍는다 |
| 실패를 잇달아 찍을 때 | 앞 화면에서 이미 틀리게 적어 두었으면 **다시 적지 않고 `탭 로그인` 만** 누른다 |
| `(5회 이상)` 처럼 횟수가 적힌 화면 | 앞에서 이미 틀린 만큼을 빼고 `되풀이 N` 으로 모자란 횟수만 채운다 |
| 입력 · 숨김 상태 · 채움 | `입력 <그 칸>=<시험 글자>` |
| 숨김 해제 · 보기 · 표시 | `탭좌표 <시안에서 찾은 아이콘 자리>` |
| 버튼 활성화 | `뒤로 → 기다림 1` |
| 팝업 · 메뉴 · 바텀시트 · 노출 · 확장 · 펼침 | 이름에 든 낱말과 같은 시안 글자를 찾아 `탭 <그 글자> → 기다림 1.2` — 띄어쓰기는 무시한다(`버스시간표 다운로드 팝업 노출` → 단추 `버스 시간표 다운로드`). 단추·입력칸 안의 글자를 제목 글자보다 먼저 고른다 |

**새 묶음의 첫 장은 앞 화면에서 들어간다 (2026-09-16).** 화면 이름의 묶음이 바뀌는 자리(`웹_로그인 화면_…` → `웹_회원 가입_…`)는
그 화면 안에서 만들 수 없다. 앞 화면 시안에서 **묶음 이름과 같은 글자**를 찾아 `탭 회원가입 → 기다림 1.2` 를 짚는다
(띄어쓰기는 무시하고, 이름이 통째로 맞을 때만 받는다). 목록 맨 첫 줄과 스플래시는 그대로 비워 둔다.

**체크를 켜야 켜지는 단추 (2026-09-16).** 뒷토막이 `… 버튼 활성화` 인데 아이디·비밀번호 칸 이야기가 아니면,
바탕 시안과 상태 시안의 **체크·라디오·토글 칸**을 맞대어 안에 표시가 새로 생긴 곳을 찾는다.
`전체 동의하기` 처럼 한 번에 켜는 것이 있으면 그것 한 번, 없으면 켜진 것들을 차례로 누른다.
누를 글자는 그 체크칸 **오른쪽에 붙은 글자**를 쓴다(체크칸에는 글자가 없다).

**이름으로 못 지으면 그림 위에서 고른다 (2026-09-15).** 동작 칸 아래 **그림에서 고르기** 를 누르면
기본 화면 시안과 만들 화면 시안이 나란히 뜨고, 시안 속 단추·입력칸 글자마다 점선 칸이 얹힌다.
"오른쪽 화면이 나오려면 왼쪽 어디를 누르나요?" 에 클릭으로 답하면 `탭 A → 탭 B → 기다림 1.2` 가 차례대로 채워진다.
점선 칸은 시안에서 그대로 뽑은 것이라 없는 글자를 적을 수 없다. 글자 없는 작은 단추는 앱에서만 자리(`탭좌표`)로 누른다.

**고르기 창은 앞 화면까지 보여 주고, 점선 칸을 넓게 연다 (2026-09-16 river 확정).**
왼쪽에 놓이는 것은 같은 묶음이면 그 묶음의 바탕 화면, **묶음의 첫 장이면 바로 앞 줄의 화면**이다.
점선 칸은 사람이 고르는 창에서만 **짧은 글자를 다 내준다** — `회원가입`·`아이디 찾기`·`전체 동의하기` 처럼
단추 이름이 안 붙은 글자가 실제로는 눌러 들어가는 자리다. 자동으로 짚을 때는 단추·입력칸 안의 글자만 본다.

**적는 칸은 "무슨 글자를 넣을까요?" 만 묻는다 (2026-09-16 river 확정).** 고르기 창에서 적는 칸은 **초록 점선**으로 보이고
(이름표도 `적는 칸 · …`), 누르면 그림 아래에 **적을 글자 칸**이 하나 생긴다. 거기에 `1234` 라고만 적으면
`입력 <그 칸>=1234` 문장은 도구가 짓는다 — 쓰는 법을 외우지 않아도 된다.
아이디·비밀번호 칸은 `<아이디>` · `<비번>` 이 미리 들어가 있다. 칸인지 아닌지는 입력 컴포넌트 안에 들어 있는지,
또는 글자가 `…입력해 주세요` 처럼 **끝이 안내 모양**인지로 본다(`입력하신 번호로 보냈어요` 같은 알림 글은 칸이 아니다).

**틀리게 적으면 고친 문장을 내민다 (2026-09-16 river 확정, `lib/actions.py` 고쳐보기).**
`<1234> 입력` 처럼 앞뒤가 바뀌었거나, `=` 가 빠졌거나, 쓸데없는 꺾쇠를 씌웠거나, 말이 조금 다를 때
(`로그인 클릭` · `2초 대기`) 빨간 글로 혼내는 대신 **"이렇게 쓰신 거죠? [이대로 바꾸기]"** 를 보여 준다.
어느 칸인지 안 적혔으면 **바로 앞에서 누른 것**을 그 칸으로 본다(`탭 인증번호 입력 → <1234> 입력`
→ `입력 인증번호 입력=1234`, 입력이 누르는 일까지 하므로 앞의 탭은 지운다).
고친 문장이 그대로 찍힐 수 있을 때만 내민다. 자동으로 바꾸지 않는다 — 단추를 누르는 것은 사람이다.

**이름으로도 못 지으면 시안 두 장을 견준다 (2026-09-15).** 바탕 화면에 없고 상태 화면에만 새로 생긴 덩어리(열린 목록·펼친 메뉴)를 찾아,
그 머리에 아랫변이 닿은 누를 글자(셀렉박스·입력칸)를 "누른 것"으로 짚어 `탭 <그 글자> → 기다림 1.2` 를 넣고 동작 칸 아래에 **짚은 근거**를 적는다.
가운데 뜨는 팝업처럼 위에 아무것도 없는 것은 짚지 않는다. 짚은 것이지 확정이 아니다 — 틀리면 사람이 고친다.

**개발 화면 글자가 시안과 살짝 달라도 찍는다 (2026-09-15 실측).** 시안 `삼성전자 기흥·화성` 이 개발에선 `삼성전자(기흥/화성)`,
`정류장명` 이 `정류장` 이었다. 정확히 없으면 화면에 보이는 것 중 **가장 닮은 것(72% 이상)** 을 누르고 촬영기록에
"시안 글자 … 가 없어 가장 닮은 … 을 썼습니다" 라고 남긴다(`lib/webshot.py`). 글자가 다른 것 자체는 검수가 다룰 일이다.
홈 화면 4장: 처음 2/4 → 닮은 글자 찾기 뒤 4/4.

**요소는 포털용 전체 목록에서 읽는다.** 플러그인이 검수 포털용으로 12단계까지 읽어 보낸 `디자인/NNN_elements.json` 을 `site/시안요소.py` 가
`속` 모양으로 바꿔 쓴다. 따로 얕게 다시 읽지 않는다(6단계짜리 `속` 은 검색줄 속 셀렉박스를 놓쳤다). 옛 꾸러미는 `속` 그대로.

**자료·계정이 그 상태여야 나오는 화면은 눌러서 못 만든다.** 뒷토막이 `1개 등록 · 미등록 · 운행 종료 · 게스트 · 권한 거부 …` 이면
동작 칸 아래에 "자료 조건 화면" 이라고 미리 표시한다(삼성통근버스 시안 402장을 세어 보니 4할쯤이 이런 화면이었다).
막지는 않는다 — 시험 계정·자료를 그 상태로 맞춰 두고 찍는 것은 사람 몫이다.

**글자는 묶음의 첫 화면(바탕)에서 찾는다.** 상태 시안에는 안내 글자가 빠져 있는 일이 많다
(예: '커서 활성화' 시안에 '비밀번호를 입력해 주세요.'가 없다). 안내 모양(입력·주세요…)이 아닌
링크 글자('비밀번호 찾기')는 칸으로 치지 않는다.

못 알아본 줄은 비워 두고 빨갛게 표시한다.

## 7-1. 로그인·스플래시 화면 기준 (모든 서비스 공통)

로그인과 스플래시는 어느 서비스에나 있고, 늘 같은 데서 어긋난다.
그래서 서비스마다 다시 정하지 않고 **아래 기준을 그대로 쓴다.**
(코드 자리: `site/동작규칙.py` · `lib/account.py` · `lib/runner.py`)

**① 시험 계정은 한 곳에만 둔다**
- 아이디·비밀번호는 ② **앱 정보**에 한 번만 적는다. 앱마다 기억해 둔다.
- 목록·이름표에는 `<아이디>` · `<비번>` · `<틀린비번>` 표식만 적힌다.
  진짜 값은 `apps/앱사전.json`(깃 제외)에만 있고, 찍는 순간에만 들어간다.
- 검수용 시험 계정만 적는다. 진짜 개인 계정은 적지 않는다.

**② 적기 전에 칸을 비운다**
- 앱이 지난번 아이디를 기억해 두는 일이 많다. 그대로 적으면 두 번 겹쳐 적힌다.
- `입력` 은 언제나 **누르고 → 비우고 → 적는다.**

**③ 실패 화면은 반드시 틀린 비밀번호로 찍는다**
- 이름에 **로그인 시도 · 유효하지 않은 · 잘못된 · 틀린 · 실패** 가 있으면 실패 화면이다.
- 맞는 비밀번호를 넣으면 로그인이 되어 버려 그 화면은 애초에 찍히지 않는다.
- 틀린 값은 적어 둔 비밀번호의 **맨 끝 한 글자만** 바꿔 만든다.
  글자를 덧붙이면 칸의 길이 제한에 잘려 도로 맞는 값이 될 수 있다.
- 목록에 `<비번>` 이라고 적혀 있어도, 실패 화면이면 찍을 때 틀린 값으로 바뀐다(안전장치).

**④ 실패를 잇달아 찍을 때는 다시 적지 않는다**
- 앞 화면에서 이미 틀리게 적어 두었으면 **로그인 단추만 누른다.** 그만큼 촬영이 빨라진다.
- 중간에 맞는 비밀번호를 적는 화면(숨김 상태 등)이 끼면 다시 적는다.
- `(5회 이상)` 처럼 횟수가 적힌 화면은 **앞에서 이미 틀린 만큼을 빼고** 모자란 횟수만
  `되풀이 N` 으로 채운다.

**⑤ 로그인 단추 글자는 시안에서 찾는다**
- 서비스마다 `로그인 / 로그인하기 / 확인 / 시작하기 / Sign in / Log in` 으로 다르다.
- 디자인 안에서 이 중 하나를 찾아 그 글자를 누른다. 못 찾으면 `로그인`.

**⑥ 스플래시는 시간을 맞추지 않는다 — 연사해서 고른다**
- 스플래시가 머무는 시간은 폰 상태·앱 캐시·첫 실행 여부에 따라 **찍을 때마다 다르다.**
  그래서 `기다림 0.1` 처럼 시간을 적어 두면 어떤 날은 홈 화면이, 어떤 날은 다음 화면이 찍힌다.
- 대신 앱을 켠 순간부터 **0.5초 동안 여러 장(보통 12장)을 찍고, 그중 한 장을 자동으로 고른다.**
  고르는 기준은 ①앱을 켜기 직전 화면과 같은 장은 버리고 ②온통 한 색인 장은 버린 뒤
  ③**0.15초 넘게 멈춰 있던 첫 구간의 마지막 장**을 집는다(로고가 다 그려지고 화면이 멈춘 첫 순간).
- '0.15초 넘게'가 필요한 까닭: 안드로이드는 앱을 켤 때 **앱 아이콘만 있는 화면**을 잠깐 스쳐
  보여 준다. 이것도 잠시 멈춰 있어서, 시간 조건이 없으면 그 장을 스플래시로 잘못 집는다.
- 동작 칸에는 **아무것도 적지 않는다.** 적어도 스플래시에서는 쓰이지 않는다.
- 고르기가 틀렸으면 `shots/…/연사기록/<사진이름>/` 에 찍은 장이 다 남아 있으니
  마음에 드는 장을 골라 덮어쓰면 된다. 고른 장에는 이름 끝에 ★ 가 붙어 있다.
- 안드로이드에서만 연사한다(폰 안에서 찍는 방식이라). iOS·웹은 예전대로 간다.

**⑦ 고친 규칙은 사이트를 다시 켜야 든다**
- 사이트는 켤 때 코드를 한 번 읽는다. 다시 켜지 않으면 옛 규칙으로 목록이 만들어진다.
- 코드를 고쳤으면 `./다시켜기.sh` 를 한 번 돌린다.

## 8. 앱 정보는 이름만 적고 **읽기**

- 앱 이름은 폰 런처 아이콘 아래 이름 그대로.
- **읽기**를 누르면 서비스 코드·앱 주소·로그인이 채워지고 **읽기 전용**이 된다. 다르면 '직접 고치기'.
- **시험 아이디·시험 비밀번호**는 언제나 고쳐 쓸 수 있다. 한 번 적으면 그 앱은 다음부터 저절로 채워진다.
- 한 번 찍은 앱은 `apps/앱사전.json` 에 저절로 쌓인다. 다음부터는 이름만 고르면 된다.

## 8-1. 사이트는 저절로 뜬다

맥을 켜면 촬영 준비 사이트가 저절로 뜬다(`http://127.0.0.1:8767`). 터미널을 열어 둘 필요가 없다.
꺼져도 스스로 다시 뜬다.

| 하고 싶은 것 | 하는 법 |
|---|---|
| 코드를 고친 뒤 새로 읽히기 | `./다시켜기.sh` |
| 잠깐 끄기 | `launchctl bootout gui/$(id -u)/com.s1.capture-site` |
| 다시 켜기 | `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.s1.capture-site.plist` |
| 처음 설치(다른 맥) | `설치/com.s1.capture-site.plist` 를 `~/Library/LaunchAgents/` 에 넣고 위 '다시 켜기' |

기록은 `site/자동실행기록.txt` 에 쌓인다(깃 제외).

## 9. 찍기 전 확인 (③)

폰 연결 · 폰 잠금 해제 · 앱 설치 — 셋 다 되기 전에는 촬영 단추가 눌리지 않는다. 잠금 해제는 사람이 한다.

## 9-1. 촬영 속도

- 같은 뜻의 기다림을 겹쳐 넣지 않는다. 동작이 '기다림 3'으로 끝나면 그 뒤에 또 기다리지 않는다.
- **자리 기억(기본 꺼짐).** 글자를 찾아 누르면 폰 화면 목록을 통째로 읽느라 한 번에 4.7초가
  들고, 자리(좌표)로 누르면 1.5초다. 그래서 처음 한 번 찾은 자리를 적어 두고 다음부터 바로
  누르는 길을 두었다 — 켜려면 뒤에 `자리기억` 을 붙인다:

      ./run.sh apps/이름표.yaml 자리기억

  **서버 응답에 따라 단추가 오르내리는 화면(로그인 실패 안내 등)에서는 켜지 않는다.**
  통근버스 로그인에서 시험해 보니 안내 글이 늦게 뜨는 사이에 헛손질이 나 두 장이 잘못 찍혔다.
  화면이 늘 같은 자리인 앱(설정 등)에서는 3장 21초 → 16초로 줄었다.
  자리가 어긋나 앞 장과 똑같은 사진이 찍히면 그 묶음의 기억을 지우고 글자로 다시 찍는다.

## 9-2. 찍는 동안 보이는 가상 마우스 (웹, 2026-09-16)

- 웹은 창을 **보이게** 찍으므로, 찍는 손이 어디를 누르는지 화살표 하나로 보여 준다.
  누를 것 한가운데로 스윽 옮겨 가 파문을 한 번 튀기고 나서 실제로 누른다.
- **사진·값에는 들어가지 않는다.** 화살표는 동작을 하는 동안에만 문서에 붙어 있고,
  값을 재고 사진을 찍기 전에 문서에서 통째로 뺀다(`lib/커서.py` 치우기).
- 창을 숨겨 찍을 때(`CAPTURE_HEADLESS=1`)는 저절로 꺼진다. 보이게 찍으면서도 끄고 싶으면
  `CAPTURE_CURSOR=0`.
- 값은 화살표가 움직이는 시간뿐이다 — 누를 것 하나에 0.15초쯤 더 걸린다(`lib/커서.py` 의 `옮기는초`·`누른뒤초`).

## 10. 검수로 보내기

- ④ 결과에서 **보낼 사진만 골라** 포털로 보낸다.
- 한 묶음(같은 화면) = 포털의 **화면 1개**, 상태 하나하나가 **검수 페이지 1장**.
- 개발 사진은 그 차수(1차)의 개발 이미지로, 시안 그림은 왼쪽 디자인 자리로 들어간다.
- 시안의 값은 `uploads/{페이지}_design.json` 으로 그림 옆에 함께 남긴다(값 대조는 다음 조각).
- 보내기 전에 포털 데이터 파일을 하루 한 번 백업해 둔다. 넣기만 하고 있는 것은 건드리지 않는다.

## 11. 겉모습

색·모서리 값은 S-1 UX 디자인시스템 토큰을 그대로 쓴다
(`s1designux/S-1-UX-DESIGN-AI-GUIDELINE` · `assets/css/tokens.css`).
읽기 전용 칸은 배경 `gray-50` · 글자 `gray-500`, 못 쓰는 칸은 그보다 흐리게. 칸 폭은 서로 맞춘다.

## 12. 하지 않는 것

- 화면을 보고 그때그때 판단해 누르는 자동 탐색(AI)은 쓰지 않는다. 대본에 적힌 대로만 움직인다.
- 오류를 자동으로 확정하지 않는다. 포털 데이터에서 무엇도 지우지 않는다.
- 앱 구조 추출(UI Automator 등)은 이 조각에서 쓰지 않는다. 화면 글자와 자리로만 움직인다.
