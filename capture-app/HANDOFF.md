## 1. 이게 뭐하는 물건인가

디자인 시안과 개발화면을 비교 검수하는 시스템이 따로 있고(포털),
**이 프로그램은 그 앞 단계 — 앱 개발화면을 화면·상태별로 자동으로 찍어서 이름 붙이는 것**만 한다.

- 검수는 하지 않는다. 비교도 하지 않는다. **찍고 이름 붙이는 것까지**가 전부다.
- 포털과의 접점은 **사진 이름 규칙 하나**뿐: `화면ID@상태.png` (예: `SET-AND-002@default.png`)
- 프로그램끼리 직접 연결하지 않는다. 폴더에 사진이 쌓이면 끝.

작업 폴더: `/Users/designgroup_02/dev-screen-qa-capture` (브랜치 `feat/app-capture`)
코드는 **`capture-app/` 안에만** 만든다. 같은 저장소의 포털 코드(`mvp0/`, `plugin-*`)는 이 조각에서 건드리지 않는다.
(검수 정책 작업과 커밋이 엮이지 않도록 일부러 분리한 작업 폴더다.)

## 3. 파일 구조와 하는 일

```
capture-app/
├─ 규칙.md                   ★ 지금까지 정한 규칙 한 장 (먼저 읽을 것)
├─ site.sh / site/           촬영 준비 사이트 (네 걸음) — server.py · design_source.py ·
│                            draft.py(찍을 목록 초안) · 동작규칙.py(동작 자동 초안) ·
│                            appbook.py(앱 사전) · intake.py(검수 포털 접수)
├─ plugin-pick/              Figma 플러그인 — 드래그로 고른 화면만 보내기(그림·글자·값 포함)
├─ run.sh                    명령어로 찍기 →  ./run.sh apps/이름표.yaml
├─ apps/                     앱 이름표(사이트가 만들어 준다) + 앱사전.json(gitignore)
├─ flows/android/            옛 공통 대본(한장씩 방식에서 쓴다)
├─ hands/android.sh          '찍는 손' — Maestro 실행
├─ lib/  nametag.py 이름표 · actions.py 동작 말 · runner.py 몰아 찍기
└─ shots/                    결과 사진 (gitignore)
```

**돌아가는 순서**
Figma 플러그인 → 사이트 ①②③ → `runner.py` 가 대본을 화면 묶음마다 한 장씩 만들어 폴더째 Maestro에 넘김
→ 사진을 `화면ID@상태.png` 로 옮기고 `찍은목록.json` 저장 → ④에서 고른 것만 검수 포털로 접수

**설계 의도(지킬 것)**
- 촬영기와 포털은 직접 붙이지 않는다. 접점은 사진 이름 규칙 하나.
- 웹을 붙일 때 바뀌는 건 `hands/` 안의 손 하나뿐.
- 같은 화면의 상태 변형은 앱을 껐다 켜지 않고 이어서 찍는다(묶음).

## 4. 이름표 쓰는 법

```yaml
앱이름: 갤럭시 설정
플랫폼: android            # android / ios / web  (지금은 android만 실제로 찍힘)
앱주소: com.android.settings   # 안드로이드 패키지 이름
서비스코드: SET             # 사진 이름 앞자리 → SET-AND-002@default.png
로그인: 없음

화면:
  - 번호: "001"
    이름: 설정 홈
    상태: default
    누를것: -            # 첫 화면 자체면 '-'
  - 번호: "002"
    이름: 연결
    상태: default
    누를것: 연결          # 첫 화면에서 이 글자를 찾아 스크롤·탭한 뒤 찍는다
```

- `nametag.py`는 일반 YAML 전부를 읽지 못한다. **위 모양만** 읽는다(값 뒤 `#` 주석은 떼어냄).
- 사진 이름: `{서비스코드}-{AND|IOS|WEB}-{번호}@{상태}.png`

## 5. 이 PC 환경 (이미 깔아 둔 것 · 걸림돌과 해결)

| 것 | 자리 |
|---|---|
| Maestro (촬영 도구, 2.x) | `~/.maestro/bin/maestro` |
| Java 21 (Maestro가 17+ 요구) | `/opt/homebrew/opt/openjdk@21` — brew로 설치함 |
| adb (안드로이드 연결) | `~/Library/Android/sdk/platform-tools/adb` |

셋 다 기본 PATH에 없다. `hands/android.sh`가 알아서 잡아 쓴다.

**이미 밟아 본 함정 3가지 (다시 밟지 말 것)**
1. 시스템 Java가 15라 Maestro 2.x가 거부한다 → `JAVA_HOME=/opt/homebrew/opt/openjdk@21`
2. Maestro 2.x는 `takeScreenshot` 경로를 마음대로 못 쓴다("resolves outside output folder").
   → `maestro test --test-output-dir=<임시폴더>` 로 주고, 사진은
   `<임시폴더>/**/takeScreenshot/<이름>.png` 에서 찾아 옮긴다. (`runner.py`의 `사진찾기`)
3. bash 변수 이름에 한글을 쓰면 안 된다(파이썬은 됨). 셸 스크립트는 ASCII 변수명만.

**폐쇄망 원칙:** `MAESTRO_CLI_NO_ANALYTICS=1` 을 손에서 켜 둔다. Maestro의 AI 자율 탐색 기능은 **쓰지 않는다**(결정 완료).

## 6. 이어서 할 때 (삼성통근버스)

1. **폰 잠금을 풀어 둔다.** 잠긴 채로는 안 찍힌다. USB 허용 창이 뜨면 '허용'.
2. 촬영 준비 사이트를 켠다 — `./site.sh` → http://localhost:8767
3. Figma에서 찍을 화면을 **드래그로 고르고** 플러그인 '촬영 준비로 보내기' → 보내기.
   (플러그인 코드가 바뀌면 Figma에서 다시 Import 해야 한다)
4. ② 목록에서 동작 초안을 눈으로 확인한다. 빨간 줄만 손대면 된다.
   메뉴를 눌러 들어가는 화면이면 '눌러 들어갈 메뉴'에 **앱에 보이는 글자**를 적는다.
   로그인이 필요한 앱이면 ②의 '앱 정보'에 **시험 아이디·시험 비밀번호**를 적는다.
   동작에는 `<아이디>` · `<비번>` 표식만 적히고, 찍는 순간에만 진짜 값이 들어간다.
5. ③ 확인 → ④ 촬영 → '검수로 보내기'로 포털에 접수.
6. 결과는 글로 설명하지 말고 **볼 것으로** 준다(사진을 data URI로 박은 HTML 한 장).

이미 알아낸 것: 앱주소 `kr.co.s1.samsungbus` · 서비스코드 `BUS` · 시험 아이디 `sambus011`.
비밀번호는 코드·문서에 적지 않는다 — ②의 '시험 비밀번호' 칸에 적으면 `apps/앱사전.json`
(깃 제외)에만 남는다. 로그인 실패 화면은 일부러 틀린 값이 필요하니 그대로 두면 된다.

## 7. 이 프로젝트에서 하지 말 것 (가드레일)

- 자동으로 오류를 "확정"하지 않는다. 최종 판단은 항상 사람(디자이너)이 한다.
- 이력은 지우지 않는다. 상태만 바꾼다.
- 포털 코드는 이 조각에서 건드리지 않는다. 촬영기는 `capture-app/` 안에서만.
- `git add .` 금지. 선택 스테이징만. **커밋 전에 멈추고 사용자에게 보고**한다.
- 유료 외부 API 금지(폐쇄망). 외부로 데이터 보내지 않는다.
- 만든 사람이 스스로 검증했다고 하지 않는다. 검증 결과는 사용자가 눈으로 보고 판정하게 한다.
