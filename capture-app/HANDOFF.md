## 1. 이게 뭐하는 물건인가

디자인 시안과 개발화면을 비교 검수하는 시스템이 따로 있고(포털),
**이 프로그램은 그 앞 단계 — 앱 개발화면을 화면·상태별로 자동으로 찍어서 이름 붙이는 것**만 한다.

- 검수는 하지 않는다. 비교도 하지 않는다. **찍고 이름 붙이는 것까지**가 전부다.
- 포털과의 접점은 **사진 이름 규칙 하나**뿐: `화면ID@상태.png` (예: `SET-AND-002@default.png`)
- 프로그램끼리 직접 연결하지 않는다. 폴더에 사진이 쌓이면 끝.

작업 폴더: `/Users/designgroup_02/dev-screen-qa-capture` (브랜치 `feat/app-capture`)
코드는 **`capture-app/` 안에만** 만든다. 같은 저장소의 포털 코드(`mvp0/`, `plugin-*`)는 이 조각에서 건드리지 않는다.
(검수 정책 작업과 커밋이 엮이지 않도록 일부러 분리한 작업 폴더다.)

## 3. 파일 구조와 하는 일

```
capture-app/
├─ run.sh                    실행 버튼 →  ./run.sh apps/galaxy-settings.yaml
├─ apps/galaxy-settings.yaml 앱 이름표 (앱마다 한 장. 새 앱 = 이 한 장만 새로 씀)
├─ flows/android/
│   ├─ shoot-home.yaml       공통 대본 — 앱 켜고 첫 화면 한 장
│   └─ shoot-menu.yaml       공통 대본 — 메뉴 글자 찾아 스크롤·탭 후 한 장
├─ hands/
│   ├─ android.sh            '찍는 손' — Maestro 실행 (안드로이드)
│   └─ web.sh                웹 자리 (비어 있음. 나중에 Playwright로 채움)
├─ lib/
│   ├─ nametag.py            이름표 읽기 (바깥 라이브러리 없이. PyYAML 안 씀)
│   └─ runner.py             화면 목록 돌며 손 호출 → 사진 이름 붙임 → 목록 남김
└─ shots/                    결과 사진 (gitignore. 커밋 안 함)
```

**돌아가는 순서**
이름표 읽기 → 화면 한 개씩 → 손(`android.sh`)이 Maestro로 대본 실행 → 임시폴더에 사진 →
`runner.py`가 `화면ID@상태.png`로 옮김 → 마지막에 `찍은목록.json` 저장

**설계 의도(지킬 것)**
- 대본은 앱이 늘어도 그대로다. 앱마다 바뀌는 값은 **전부 이름표**에서 온다.
- 웹을 붙일 때 바뀌는 건 `hands/` 안의 손 하나뿐. 이름표·이름 규칙·결과 폴더·실행 버튼은 그대로 쓴다.
- 화면 한 장마다 앱을 껐다 켠다(`stopApp` → `launchApp`). 느리지만 화면끼리 서로 오염되지 않는다.

## 4. 이름표 쓰는 법

```yaml
앱이름: 갤럭시 설정
플랫폼: android            # android / ios / web  (지금은 android만 실제로 찍힘)
앱주소: com.android.settings   # 안드로이드 패키지 이름
서비스코드: SET             # 사진 이름 앞자리 → SET-AND-002@default.png
로그인: 없음

화면:
  - 번호: "001"
    이름: 설정 홈
    상태: default
    누를것: -            # 첫 화면 자체면 '-'
  - 번호: "002"
    이름: 연결
    상태: default
    누를것: 연결          # 첫 화면에서 이 글자를 찾아 스크롤·탭한 뒤 찍는다
```

- `nametag.py`는 일반 YAML 전부를 읽지 못한다. **위 모양만** 읽는다(값 뒤 `#` 주석은 떼어냄).
- 사진 이름: `{서비스코드}-{AND|IOS|WEB}-{번호}@{상태}.png`

## 5. 이 PC 환경 (이미 깔아 둔 것 · 걸림돌과 해결)

| 것 | 자리 |
|---|---|
| Maestro (촬영 도구, 2.x) | `~/.maestro/bin/maestro` |
| Java 21 (Maestro가 17+ 요구) | `/opt/homebrew/opt/openjdk@21` — brew로 설치함 |
| adb (안드로이드 연결) | `~/Library/Android/sdk/platform-tools/adb` |

셋 다 기본 PATH에 없다. `hands/android.sh`가 알아서 잡아 쓴다.

**이미 밟아 본 함정 3가지 (다시 밟지 말 것)**
1. 시스템 Java가 15라 Maestro 2.x가 거부한다 → `JAVA_HOME=/opt/homebrew/opt/openjdk@21`
2. Maestro 2.x는 `takeScreenshot` 경로를 마음대로 못 쓴다("resolves outside output folder").
   → `maestro test --test-output-dir=<임시폴더>` 로 주고, 사진은
   `<임시폴더>/**/takeScreenshot/<이름>.png` 에서 찾아 옮긴다. (`runner.py`의 `사진찾기`)
3. bash 변수 이름에 한글을 쓰면 안 된다(파이썬은 됨). 셸 스크립트는 ASCII 변수명만.

**폐쇄망 원칙:** `MAESTRO_CLI_NO_ANALYTICS=1` 을 손에서 켜 둔다. Maestro의 AI 자율 탐색 기능은 **쓰지 않는다**(결정 완료).

## 6. 다음 할 일 — 삼성통근버스 앱 찍기

사용자가 원하는 다음 대상은 **삼성통근버스** 앱이다. 이미 폰에 깔려 있다.

이미 알아낸 것:
- 패키지(앱주소): **`kr.co.s1.samsungbus`**
- 첫 화면: `kr.co.s1.samsungbus/.ui.splash.SplashActivity`

절차:
1. **폰 잠금을 풀어 둔다.** (잠긴 채로는 앱 화면이 안 찍힌다 — 확인함. 잠금 해제는 사람이 한다)
2. 앱을 켜서 화면 하나씩 보고, 눌러 들어갈 **메뉴 글자**를 받아 적는다.
   화면 확인은 `adb exec-out screencap -p > 파일.png` 로 찍어서 보면 된다.
3. `apps/samsung-bus.yaml` 이름표를 새로 쓴다. 서비스코드는 사용자와 정한다(예: `BUS`).
   화면 번호도 사용자(디자이너)가 쓰는 포털 번호에 맞춰야 하므로 **임의로 정하지 말고 물어본다.**
4. `./run.sh apps/samsung-bus.yaml` 실행.
5. 결과를 **글로 설명하지 말고 볼 것으로** 준다 — 찍힌 사진들을 HTML 한 장(사진을 data URI로 박은 파일)으로
   만들어 보여 준다. 조각 A에서도 그렇게 했다.

**주의할 점**
- 로그인이 필요하면 이름표의 `로그인:` 칸에 계정 이름만 적고, **비밀번호는 코드·이름표에 넣지 않는다.**
  로그인 자동화가 필요하면 사용자와 먼저 상의한다.
- 표 안 숫자·목록 건수 같은 **서버에서 오는 값은 검수 예외**다. 고정하려 애쓰지 않는다.
- 사진에 폰 맨 위 시계·배터리 줄과 맨 아래 손잡이 줄이 같이 찍힌다. **잘라내는 일은 이 조각이 아니라
  다음 조각(B, 포털 접수함)에서** 한다. 여기서 하지 말 것.

## 7. 이 프로젝트에서 하지 말 것 (가드레일)

- 자동으로 오류를 "확정"하지 않는다. 최종 판단은 항상 사람(디자이너)이 한다.
- 이력은 지우지 않는다. 상태만 바꾼다.
- 포털 코드는 이 조각에서 건드리지 않는다. 촬영기는 `capture-app/` 안에서만.
- `git add .` 금지. 선택 스테이징만. **커밋 전에 멈추고 사용자에게 보고**한다.
- 유료 외부 API 금지(폐쇄망). 외부로 데이터 보내지 않는다.
- 만든 사람이 스스로 검증했다고 하지 않는다. 검증 결과는 사용자가 눈으로 보고 판정하게 한다.
