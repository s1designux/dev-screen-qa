# 규칙 한 바퀴

검수기의 판정 규칙은 **아무나 아무 때나 바꾸지 않는다.** 한 건이 지나는 길이 정해져 있고,
그 길의 검문소를 프로그램이 지킨다. 이 스킬은 그 길을 끝까지 끌고 가는 순서다.

**왜 이렇게 하나:** 예전에는 한 세션이 만들고 스스로 재서 늘 "통과"였다. 정답 몇 건만 남기고
나머지를 숨겨도 성적이 좋아 보이는 구멍이 있었다. 그래서 **만든 손과 재는 손과 보는 눈을 나눈다.**

## 자리 셋 (`.claude/agents/`)

| 자리 | 하는 일 | 절대 안 하는 일 |
|---|---|---|
| 운영 | river 창구 · 제안 등록 · 승인 받기 · 양면 시험지 만들기 · 보고 | 코드 수정, 숫자 직접 적기 |
| 구현 | 승인된 범위만 코드로 | 시험지 열기, 자기 숫자를 성적이라 말하기 |
| 독립검토 | 범위 준수 확인 · 공식 성적 읽기 · 반례 만들기 | 코드 수정, 숫자 만들기 |

## 걸음

**0. 지금 어디인지 본다**

```
python3 규칙장부/도구/장부보기.py            # 제안별 지금 상태
python3 규칙장부/도구/장부보기.py <제안>      # 그 제안의 사건 전부
```

이미 있는 제안이면 새로 등록하지 않고 그 뒤를 잇는다. 보류된 것은 보류 사유부터 본다.

**1. 등록 (운영)** — 근거를 갖춰 올린다. 범위가 넓을수록 근거도 넓어야 한다.

| 적용 범위 | 확인할 근거 |
|---|---|
| 요소·화면 예외 | 그 사례 · 정확한 대상 · 다시 적용을 멈출 조건 |
| 서비스 공통 | 서로 다른 화면·조건에서 같은 원인(같은 양식 복제본은 근거가 아니다) |
| 시스템 기본 | PC/모바일/앱에 미치는 영향 + 잘못 빠질 반례 |

```
python3 규칙장부/도구/장부적기.py 등록 P17 --내용 "…" --적은이 "운영 AI"
```

**2. river 범위·기준 승인** — 여기서 **멈춘다.** 무엇을·왜 정해야 하는지·선택지·안 정하면 어떻게 되는지를 함께 묻는다.
승인이 오면 승인번호를 받아 쌓는다(`장부적기.py 승인 … --승인번호 A-…`).

**3. 양면 시험지 (운영)** — `시험지/양면/<제안>.json` 한 장.
드러나야 할 것과 **그대로 접혀 있어야 할 것**을 함께 적는다. 한 쪽만 적으면 시험이 아니다.

**4. 구현** — 승인 범위만. 알고리즘은 검수기에, 값은 포털 DB에.

**5. 공식 측정 + 양면 시험**

```
python3 규칙장부/도구/공식측정.py --이름 "P17 넣은 판"
python3 규칙장부/도구/양면시험.py P17 <측정번호>
python3 규칙장부/도구/장부적기.py 측정 P17 --측정번호 <측정번호> --적은이 프로그램
```

한 화면이라도 못 재면 '통과'가 아니라 **판정 불가**다. 떨어지면 구현으로 돌아간다 — **두 번까지**.

**6. 독립 검토** — 빈 기억으로 본다. 볼 것이 줄었다면 무엇이 사라졌는지 가른다.
쓸 만한 반례는 양면 시험지의 '접혀 있어야 할 것'으로 올린다.

**7. 문지기**

```
python3 규칙장부/도구/문지기.py P17
```

승인번호 · 승인 뒤의 공식 성적 · 양면 두 쪽 · 독립 검토 통과 · 잰 뒤 검수기와 시험지가 그대로인지.
하나라도 비면 문이 닫힌다. **우회하지 않는다** — 닫힌 이유를 그대로 river에게 전한다.

**8. river 적용 승인** — 마지막 문은 사람이 연다. 승인 뒤 `장부적기.py 반영`.

## 지키는 선

- 자동 검수 결과를 사람 대신 '확정'으로 올리지 않는다(CLAUDE.md 2번-2).
- 이력은 지우지 않는다. 잘못 적었으면 `바로잡음` 사건을 새로 쌓는다.
- 시험지는 구현이 고치지 않는다. 고쳐야 하면 멈추고 river에게 올린다.
- 성적은 프로그램만 적는다. 옛 기록의 숫자(647·529·440·331·457)는 조건이 달라 **참고 기록**이다.

## 테스트 시나리오

**정상 흐름** — "노선관리 표의 항목 이름이 안 보인다"
→ 장부보기에서 P1(보류) 확인 → 보류 사유(근거 화면 1개)를 풀 근거를 모아 river에게 승인 요청
→ 승인번호 받음 → 양면 시험지 작성 → 구현 → 공식 측정 → 양면 시험 → 독립 검토 → 문지기 → river 적용 승인.

**막히는 흐름** — 측정을 마친 뒤 검수기를 한 줄 더 고쳤다
→ 문지기가 "측정한 뒤 검수기가 바뀌었다"로 문을 닫는다 → 다시 재고 양면 시험도 다시 본다.
고친 것을 되돌려 문을 여는 길로 가지 않는다.
