# 개발화면 검수기

여러 디자인 프레임과 여러 개발 캡처를 **Figma 캔버스의 같은 행끼리 비교**하고, 자동 정렬 뒤 다른 영역을
후보 번호로 표시하는 로컬 Figma 플러그인입니다. 외부 API와 AI 토큰을 사용하지 않습니다.

## 설치

1. Figma 데스크톱 앱 → **Plugins → Development → Import plugin from manifest…**
2. 이 폴더의 `manifest.json` 선택
3. **개발화면 검수기** 실행

## 사용 흐름

1. 디자인 원본과 개발 캡처를 한 행에 하나씩 나란히 배치합니다.
   - 왼쪽에는 디자인 원본, 오른쪽에는 개발화면 캡처본을 둡니다.
   - 한 행에는 디자인 1개와 개발 캡처 1개만 둡니다.
2. 검수할 디자인 프레임과 Figma에 이미 올린 개발화면 이미지를 모두 드래그해 선택합니다.
   - 디자인 프레임과 개발화면 이미지를 함께 선택해도 자동으로 구분합니다.
3. **검수 시작** — 선택 자료를 읽고 같은 행의 두 자료를 자동으로 찾아 정렬·겹침·차이 찾기를 실행
4. 패널 번호를 눌러 개발 캡처 위 표시와 살아 있는 디자인 레이어를 함께 포인팅. 반대로 **캔버스에서 번호를 누르면 패널 목록의 그 번호로 옮겨가 잠깐 강조**됩니다(다른 화면의 번호면 그 화면으로 넘어갑니다).
   - 번호가 아니라 **검수 화면(결과 프레임)을 눌러도** 패널이 그 화면의 검수 내용으로 바뀝니다. 그 화면의 나란히 보기 카드나 검수 레포트를 눌러도 같습니다. 화면 제목이 잠깐 파랗게 바뀌어 바뀐 것을 알려 줍니다.
   - 번호를 누르면 패널에 **나란히 보기**(디자인 조각 | 개발 조각, 같은 배율)가 열립니다. 글자 내용처럼 겹쳐서는 읽기 어려운 것을 디자인 프레임으로 이동하지 않고 대조할 수 있습니다.
   - 나란히 보기는 **캔버스에만** 표시합니다(플러그인 패널 안에는 그리지 않습니다). 패널의 **나란히 보기: 켬/끔** 버튼으로 켜고 끕니다. 끄면 카드를 만들지 않고 이미 있던 카드도 지웁니다. 번호를 고르면 **그 번호와 같은 높이**에 "나란히 보기" 카드가 만들어지고, 번호와 카드를 파란 선으로 잇습니다. 카드에는 디자인 조각·개발 조각(각 520px)과 사유·디자인 원본값이 들어 있고, 화면은 번호와 카드가 함께 보이도록 맞춰집니다. 패널은 좁은 폭(390px) 그대로입니다.
   - 카드는 **번호 바로 옆(오른쪽 32px)** 에 붙습니다. 검수 화면 일부를 가리더라도 번호와 카드를 한눈에 보기 위해서입니다. 번호가 화면 오른쪽 끝에 가까우면 번호 왼쪽에 붙습니다. 선택을 지우면 카드가 사라져 화면이 다시 보입니다.
   - 카드는 번호를 바꿀 때마다 갱신되고, 선택을 지우거나 다른 화면으로 넘어가면 사라집니다.
   - 선택한 번호는 패널 목록에서도 자동으로 보이게 스크롤됩니다. 패널 폭은 390px로 고정입니다.
   - **검수 범위** 카드는 접힌 상태가 기본이며 한 줄 요약("디자인 위 101px 제외 · 개발 위 119px 제외")만 보여줍니다. 제목을 누르면 펼쳐집니다. 확인이 필요한 상태(제외되지 않은 띠가 있음)면 자동으로 펼쳐집니다.
   - **디자인 원본값은 살아 있는 값이다 (2026-09-09).** 번호를 고르면(패널·캔버스 어느 쪽에서든) 그 번호가 가리키는 디자인 레이어를 **그 순간 Figma에서 다시 읽어** 목록의 번호 밑에 보여 준다(글자: 크기·굵기·글꼴·줄높이·색 / 도형: 크기·배경·테두리·둥글기). 검수 시작 때 찍어 둔 값과 다르면 바뀐 줄을 주황으로 표시하고 "검수 뒤 디자인이 바뀌었어요 — 다시 검수해야 번호가 맞아요"라고 알린다. 레이어가 지워졌으면 그렇게 말한다. **판정은 건드리지 않는다**(자동으로 오류를 확정하거나 풀지 않음). 나란히 보기 카드에도 지금 값과 같은 안내가 실린다. 개발 쪽 값은 여전히 추측하지 않는다.
5. 필요할 때만 **겹쳐보기**로 사람이 추가 확인
6. 번호는 **기본이 '오류 확정'** — 사람은 아닌 것만 골라낸다
   - 찾은 차이는 모두 **오류 확정**으로 들어옵니다. 오류가 아닌 것에만 **제외(오류 아님)** 를 누르면 됩니다. 따로 손대지 않은 번호는 그대로 오류로 봅니다. ('보류' 상태는 없앴습니다.)
   - 화면 제목 아래 **이 화면: 공통화면(문구 고정) / 일반화면(데이터 가변)** 스위치가 있습니다. 화면 이름(로그인·회원가입·아이디/비밀번호 찾기·약관·오류·빈 상태)으로 자동 추정하고, 바꾸면 디자인 프레임에 저장돼 다음 검수에도 그대로 씁니다. 사람이 정한 설정(화면 종류·글자 가변/고정·검수 범위·겹쳐보기 위치)은 Figma 공유 칸(`devScreenQa`)에도 같이 적혀, 포털이 프레임을 읽어올 때 함께 가져갑니다(검수 결과·번호 판정은 옮기지 않음).
   - 목록 맨 아래 **가변 글자·요소 N건** 묶음(기본 접힘)에는 숫자·날짜·표 데이터처럼 바뀔 수 있는 글자와 반복 행 안의 칩·아이콘이 들어갑니다. 오류로 세지 않지만 숨기지도 않습니다. 고정 문구라면 **고정**을 눌러 오류 후보로 올리고, 반대로 오류 확정 글자 행에서 **가변**을 누르면 묶음으로 내립니다. 사람이 누른 판정은 그 글자(디자인 노드)에 기억됩니다.
7. **검수 레포트 작성** — 검수 화면 오른쪽에 메모장을 만듭니다. 화면 이름·날짜·건수 요약·검수 범위와 번호별 상태·사유·상세·디자인 원본값이 번호 순서대로 적힙니다. 다시 누르면 최신 판정으로 새로 만듭니다.

## 비교 방식 (1.0 → 요소 우선 비교로 개편, 2026-09-02)

1. **원본 해상도로 읽기.** 디자인 프레임과 개발 캡처를 모두 원본 크기(최대 4096px)로 읽습니다. 24px 아이콘, 10px 푸터 글자, 1px 테두리도 비교 대상이 됩니다.
2. **구역별 정렬.** 디자인의 큰 묶음(헤더·본문·푸터 등)마다 개발 캡처에서 자기 자리를 따로 찾습니다. 전체를 한 가지 오프셋으로 맞추지 않으므로 푸터가 헤더와 다르게 밀려 있어도 됩니다.
3. **검수 범위 정하기(틀 띠 제외, 2026-09-02).** 비교 전에 "진짜 검수할 화면이 어디부터인지"를 양쪽에서 정합니다.
   - 디자인 쪽: 화면 위·아래 끝에 붙은 가로로 꽉 찬 얇은 구역 중 ① 이름·글자(URL·시계)로 브라우저 틀·상태바가 분명한 것, ② 개발 캡처에서 짝이 없는 것, ③ 개발 캡처 바깥에 해당하는 것, ④ 짝을 찾았어도 본문과 가로 밀림이 다른 것(가짜 탭바가 진짜 크롬 탭에 붙은 경우)을 틀로 보고 제외합니다.
   - 개발 캡처 쪽: 디자인 내용이 시작되는 자리가 캡처의 몇 px에 닿는지 계산해, 그 위쪽 띠(브라우저 탭·주소창·북마크, 상태바)를 찾습니다. 가로 경계선에 맞춰 다듬은 뒤 **디자인에도 틀이 있을 때만** 자동으로 잘라내고 다시 정렬·비교합니다. 디자인에 틀이 없는데 캡처에만 띠가 있으면 진짜 추가 요소일 수 있어 자르지 않고 안내만 합니다.
   - 패널의 **검수 범위** 카드에서 양쪽 제외 폭을 보여 주고, **조정**으로 캡처 미리보기 위의 붉은 선을 끌어 직접 정할 수 있습니다. 정한 값은 캡처 노드에 저장돼 같은 캡처를 다시 검수할 때 그대로 씁니다. 캔버스 결과 프레임에는 제외 띠가 흐리게, 검수 범위가 점선으로 표시됩니다.
4. **요소 우선 비교.** Figma 요소(글자·아이콘·테두리나 배경이 있는 도형)마다 그 자리를 비교해 누락 / 위치 이동 / 글자 내용·모양·색 / 아이콘 / 모양·크기 후보를 만듭니다. 요소 검사에서 "같다"고 본 자리는 픽셀 비교가 다시 후보를 만들지 않습니다.
5. **빈자리 픽셀 비교.** 요소가 없는 곳만 픽셀 블록으로 비교해 개발에만 있는 요소 등을 찾습니다.
6. **글자 후보는 독립.** 글자 차이는 다른 후보에 흡수되지 않고 항상 자기 번호를 가지며, 패널에 디자인 원문("디자인 글자: …")을 함께 보여 사람이 대조할 수 있게 합니다. 긴 글자줄은 토막 내어 일부만 바뀐 자리를 짚습니다.
7. **글자 가변·불가변 판정 (2026-09-03).** 글자 자체가 아니라 "어디에 놓인 글자인지"로 정합니다. 순서대로 먼저 맞는 규칙이 이깁니다.
   - ① 사람이 누른 판정(가변/고정) → ② 글자 꼴·문구: 숫자·쉼표숫자·날짜·시간·전화번호·%·홍길동 같은 자리표시 값은 **가변**, "…해 주세요/…입니다" 같은 안내 문구와 사업자번호·© 회사 정보는 **고정** → ③ 컴포넌트 역할(글자가 묶인 속성 이름, 글자·부모 레이어 이름): Button·Label·Placeholder·Title·Header·Tab·Menu·Footer·Toast 등은 **고정**, Table Cell·Row·Value·List item 등은 **가변**(같은 이름 안에서는 고정 낱말이 이김: 표 안의 버튼은 버튼) → ④ 반복: 같은 부모 아래 같은 크기 묶음이 3개 이상, 두 줄 이상 쌓여 있고 각각 안에 요소가 2개 이상이면 데이터 행(표·목록·카드)으로 보고 그 안은 **가변**(가로 한 줄 반복인 탭·메뉴는 아님) → ⑤ 이름 없는 버튼 모양(채움·테두리 상자 안에 글자 하나가 가운데)은 **고정** → ⑥ 나머지는 화면 종류: 공통화면이면 고정, 일반화면이면 가변.
   - 가변으로 본 글자는 **내용 차이만 오류로 세지 않습니다.** 글자색·글자 높이 차이는 그대로 검토 후보로 남고, 누락·간격도 그대로입니다. 반복 행 안의 칩·아이콘·도형은 데이터에 따라 자리·내용이 바뀌므로 위치·모양·색 후보를 묶음으로 내립니다(누락은 유지).
   - 판정은 다시 비교하지 않고 후보의 묶음만 바꾸므로 스위치·버튼 반응이 즉시입니다. 원래 판정은 남겨 두어 되돌릴 수 있습니다.

## 캔버스에 표시되는 것

- 개발 캡처 원본 비율을 유지한 프레임
- 검토 후보 번호와 틀린 영역 사각형
- 후보 분류 라벨: 요소 추가·누락, 위치·정렬·크기, 색상·모양, 아이콘·이미지, 글자 내용·모양·영역 차이
- 컴포넌트 사이 간격 차이: 두 컴포넌트 테두리와 빈 공간의 색상 띠·측정선
- 검수 레포트 메모장: 번호별 상태·사유·상세·디자인 원본값(검수 화면 오른쪽)
- 나란히 보기 카드: 고른 번호의 디자인 조각과 개발 조각(그 번호와 같은 높이, 화면 바깥쪽에 연결선으로 이어짐)
- 겹쳐보기: 검수 결과 프레임 위에 디자인 이미지를 반투명으로 얹어 그 자리에서 확인.
  디자인의 브라우저 틀 띠는 잘라서 얹고, 개발 캡처에서 잘라낸 띠(브라우저 탭·주소창)만큼 내려서 **내용 맨 위끼리** 맞춥니다.
  자동 자리가 맞지 않으면 **캔버스에서 그대로 끌어** 맞춥니다. 겹쳐보기를 켜면 겹쳐놓은 디자인이 선택된 상태로 뜨므로 바로 끌거나 방향키로 옮길 수 있고,
  옮긴 자리는 **자동으로 저장**됩니다(개발 캡처 노드에 저장 · 겹쳐보기를 껐다 켜거나 다시 검수해도 유지). 따로 누를 버튼은 없습니다.
  저장하는 값은 자동 자리로부터의 차이라, 검수 범위를 바꿔도 보정이 따라갑니다. 자동 자리로 되돌리려면 원래 자리로 다시 끌어다 놓으면 됩니다.
  세로 자리를 기준 요소 정렬값에만 맡기면 기준이 적을 때 수십 px씩 흔들려, 사람이 보기에 크게 어긋나기 때문입니다.
  **자리를 옮기면 그 화면의 검수내역은 리셋됩니다.** 옮긴 자리 기준으로는 이전 번호가 더 이상 맞지 않기 때문에,
  패널 목록과 캔버스의 번호를 지우고 **‘재검수 진행’** 버튼을 띄웁니다(겹쳐놓은 디자인·개발 캡처는 그대로 둡니다).
  버튼을 누르면 **사람이 맞춘 자리를 정렬 기준으로 삼아** 그 화면만 다시 비교합니다(정렬식의 tx·ty에 반영, 보정은 누적).
  다시 비교한 뒤 겹쳐보기를 켜면 사람이 맞춘 그 자리에 그대로 얹힙니다.
- 검수 범위: 비교에서 뺀 개발 캡처 위쪽 띠(흐림) + 실제 비교 범위(파란 점선)

개발 캡처만 보고 개발 쪽의 정확한 px 값을 추측하지 않습니다(위치 이동·간격은 "약 Npx"). 자동 결과는 전부 후보이며,
사용자가 **오류 확정**한 번호만 오류로 취급합니다.

## 한계

- 비교할 자료는 캔버스의 같은 행을 기준으로 찾습니다. 한쪽이 빠지거나 같은 종류가 두 개 이상인 행은 먼저 배치를 고쳐야 합니다.
- 글자 판독(OCR)은 하지 않습니다. 글자 차이는 모양·밝기 패턴으로만 판단하므로 **10px 안팎 작은 글자에서 몇 글자만 바뀐 것**(예: 대표이사 이름)은 "글자 수나 띄어쓰기가 달라 보임" 정도로만 잡히거나 놓칠 수 있습니다. 디자인 원문을 보고 눈으로 대조해 주세요.
- 개발 캡처의 글꼴이 디자인과 다르면(폴백 글꼴 등) 글자 후보가 늘어납니다. 이때는 "폰트 모양" 또는 "글자 내용" 라벨로 나옵니다.
- 한 구역 안에서 왼쪽 묶음과 오른쪽 묶음이 서로 다른 방향으로 밀린 경우(헤더 로고는 오른쪽으로, 유틸리티는 왼쪽으로) 한쪽이 누락·추가로 나올 수 있습니다.
- 캡처 속 동적 데이터, 애니메이션, 글자 렌더링 차이는 후보를 늘릴 수 있습니다.
- 겹쳐보기는 화면 전체에 한 가지 자리·배율만 적용합니다. 개발 화면의 세로 길이가 디자인과 다르면(브라우저 창 높이 차이 등) 아래로 갈수록 벌어져 보입니다. 구역별로 따로 맞춘 것은 번호(핀)와 나란히 보기입니다.
- 검수 범위 자동 판정은 위쪽 띠 기준입니다. 아래쪽 띠(모바일 제스처바 등)는 디자인 쪽 틀만 제외하고, 캡처 아래쪽은 아직 자르지 않습니다. 디자인에 틀이 없고 캡처에만 위쪽 띠가 있을 때는 사람이 ‘검수 범위 › 조정’에서 결정해야 합니다.
- 가변 글자 판정은 피그마가 정리돼 있을수록 정확합니다. 컴포넌트 없이 맨 텍스트로 그린 일반화면에서는 컬럼 제목·탭 같은 고정 문구도 "가변" 묶음으로 내려갈 수 있습니다(숨기지는 않음 · 사람이 **고정**을 누르면 기억). 가변으로 본 글자의 진짜 오타는 못 잡으므로 묶음을 펼쳐 눈으로 확인해야 합니다. 사람이 누른 판정은 피그마 노드 기준이라 그 글자를 지우고 새로 그리면 기억이 풀립니다.
- 같은 글꼴·같은 크기의 짧은 글자를 같은 길이로 바꿔치거나(예: "조회"→"검색"), 작은 글자(13~14px) 뒤에 글자가 더 붙는 경우(예: "연락처"→"담당자 휴대전화번호")는 디자인 글자 상자 안의 윤곽만 보는 현재 엔진이 "같다"고 볼 수 있습니다. 개발 캡처의 글꼴이 다를 때는 잘 잡힙니다. (표 재현 세트에서 확인된 별건의 엔진 한계)
- 컴포넌트 안의 안쪽여백은 간격 후보에서 제외합니다. 컴포넌트 경계가 분명하지 않으면 간격 후보를 만들지 않을 수 있습니다.
- 긴 이미지는 Figma 이미지 제한에 맞춰 표시용 사본만 축소합니다. 비교 좌표는 원본 기준으로 계산합니다.
- Figma 캔버스 이미지는 보이는 자르기·비율을 포함해 PNG로 읽습니다. 이미지 채움이 없는 일반 도형이나 내부 요소가 있는 디자인 프레임은 개발 캡처로 오인하지 않습니다.
- 포털 SQLite 동기화는 아직 하지 않습니다. 포털이 원본이라는 프로젝트 원칙은 그대로 유지합니다.
- Figma 실제 실행 검증은 데스크톱 앱에서 별도로 확인해야 합니다.

## 담당자용 숨은 도구 — 검수 자료 내보내기 (2026-09-08)

**검수하는 사람에게는 안 보인다.** 헤더의 제목 「개발화면 검수기 1.0Ver」을 **세 번 클릭**하면 노란 막대가 나타난다.

`검수 자료 내보내기` 를 누르면, 플러그인이 이미 읽어둔 것을 파일로 저장한다:

| 파일 | 내용 |
|---|---|
| `elements_<프레임이름>.json` | 요소 목록 (재현 하네스 `validation-image-qa/repro/run.js` 가 그대로 읽는 모양) |
| `design_<프레임이름>.png` | 디자인 원본 |
| `dev_<개발화면이름>.png` | 개발화면 캡처 |

**용도:** 검수 규칙을 발굴할 때 실제 화면을 재현 세트로 옮기기 위한 것. 사용자에게 배포하는 기능이 아니다.
**밖으로 나가는 것은 없다**(폐쇄망) — 브라우저가 로컬로 저장할 뿐이다. 검수 판정 로직은 건드리지 않는다.

`ui.html` 만 고쳤고 `code.js`·`manifest.json` 은 그대로다(요소·이미지를 읽는 기능은 이미 있었다).
