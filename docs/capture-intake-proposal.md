# 촬영본 가져오기 → Figma 디자인 연결 구성안

> 최초 제안 기록입니다. 이후 사용자 요청으로 [포털 3단계 흐름](portal-flow-revision.md)으로 수정했습니다.

2026-09-09 · 구현 승인 전 제안. 실행 코드·DB·촬영기·Figma 원본 변경 없음.

## 기존 구조에 붙이는 위치

화면 목록의 우측 상단에 **촬영본 가져오기**, 옆에 **접수함**을 둔다.

촬영본 가져오기 → 이름·상태 확인 → Figma 디자인 연결·짝 확인 → 기존 검수 페이지 상세.

기존 화면 목록 → 검수 페이지 목록 → 좌우 비교 구조는 유지한다. 로그인은 화면 하나, 8개 촬영 상태는 그 안의 검수 페이지로 구성한다. 같은 모습으로 되돌아온 촬영본도 각각 유지하며 같은 디자인 프레임을 연결할 수 있다. 상태와 재검수 차수를 혼동하지 않는다.

## 1. 가져오기·이름 확인

- 제목: 촬영본 가져오기. 폴더 선택 또는 PNG 여러 장과 찍은목록.json 선택.
- 프로젝트 선택을 상단에 둔다. 이번 시험은 ‘삼성통근버스 앱’이라는 임시 프로젝트명을 제안하고 기존 프로젝트를 선택할 수도 있게 한다. 프로젝트명은 공식 서비스코드와 별개이며 기존 웹 프로젝트에 자동 합치지 않는다.
- 목록 파일이 있으면 화면명·상태·촬영일·해상도·촬영방법을 읽는다. 없으면 파일명에서 이름을 제안하고 수정하게 한다. 없는 기기 정보는 추정하지 않는다.
- 표: 사진 미리보기 / 화면 이름 / 상태 / 가져오기 상태 / 이번 연결 대상.
- 이번 자료는 총 10장, 로그인 8장 연결 대상, 찾기 2장 제외로 표시한다. 제외 사유는 ‘본문 미표시, 원인 미확인’. 제외해도 접수 기록과 원본은 보존한다.
- 화면 번호: ‘미정’. 임의 서비스코드나 공식 번호를 만들지 않는다.
- 하단 버튼: **접수 저장하고 디자인 연결**. 도중에 나가도 저장된 접수함에서 이어서 작업한다.
- 파일 누락·읽을 수 없는 PNG는 해당 행에 표시한다. 같은 파일을 다시 가져오면 중복을 알려 기존 접수본을 유지하는 것이 기본이다. 실패한 파일을 성공으로 세지 않는다.

## 2. 디자인 연결·짝 확인

- 상단: ‘로그인 · 연결 확인 0/8’, Figma 원본 링크 입력, **디자인 불러오기**.
- 좌측 좁은 목록: 8개 촬영 상태와 ‘디자인 미연결 / 짝 확인 대기 / 짝 확인됨 / 보류’ 표시.
- 중앙: 왼쪽 디자인, 오른쪽 촬영본. 이미지 전체를 각각 비율 유지하여 표시한다.
- 디자인 선택 영역: 링크 범위에서 확인 가능한 프레임을 이름과 미리보기로 선택. 범위가 맞지 않으면 개별 프레임 링크로 변경할 수 있다. Figma에서 현재 선택한 항목과 링크 대상이 동일하다고 가정하지 않는다.
- 하단: **이 짝으로 확인하고 다음**, **보류**. 확인은 ‘대응하는 디자인과 촬영본이 맞다’는 뜻이며 오류 확정이나 검수 통과가 아니다.
- 동일 프레임을 여러 촬영 상태에 재사용할 수 있다. 대응 시안이 없으면 보류하고 이유를 남긴다. 8장 모두 대응 시안이 있다고 가정하지 않는다.
- 연결 변경 시 이전 연결·확인 기록은 남기고 새 짝을 다시 확인한다.
- 불러오기 실패는 ‘권한 확인 필요 / 링크 대상 확인 필요 / 다시 시도’로 구분한다. 링크만 저장된 상태를 이미지 연결 성공으로 표시하지 않는다.

## 3. 기존 검수로 이동

- **확인한 페이지 검수 시작**으로 사람의 짝 확인이 끝난 페이지만 기존 좌우 비교에 연결한다. 일부 보류 상태여도 확인된 페이지부터 시작할 수 있다.
- 화면 목록: 로그인 / 화면 번호 미정 / Android / 검수 페이지 수. 준비 중인 접수 항목은 접수함에서 찾는다.
- 페이지 목록: 기본, 아이디 입력 중, 아이디만 입력, 두 칸 입력·숨김, 비밀번호 보기, 다시 숨김, 비밀번호 삭제, 전체 삭제.
- 페이지 상세: 기존 좌우 비교·핀·카드 배치 유지. 디자인 쪽에 **Figma 원본 열기**, **연결 변경**을 추가한다.
- 새 접수로 만든 페이지에서는 기존 즉시 덮어쓰기 업로드 버튼 대신 접수·연결 변경 흐름을 사용한다. 디자인이나 촬영본 교체는 이전 파일·연결 기록을 보존하고 짝 확인을 다시 받는다. 기존 핀이 있는 페이지의 촬영본 교체는 이번 범위에서 제공하지 않는다.
- 새 페이지는 ‘미검수’, 이슈 0건으로 시작한다. 이슈가 없다는 이유로 PASS를 부여하지 않는다.
- 현재 화면 종합 판정은 FAIL 페이지가 없으면 PASS로 계산하므로 수정이 필요하다. FAIL이 하나라도 있으면 FAIL, 전부 명시적으로 PASS일 때만 PASS, 나머지는 ‘미검수 포함’으로 표시한다.
- 이번 조각은 검수 준비 및 기존 상세로의 진입까지다. 새로운 핀 작성·자동 비교·재검수 차수 추가 기능은 포함하지 않는다.

## 최소 구현 범위

1. 로컬 포털의 접수함과 여러 파일 가져오기, 이름·상태 수정, 제외·보류·재개.
2. Figma 링크를 통한 읽기 전용 프레임 조회·이미지 가져오기와 사람이 짝 확인하는 화면.
3. 확인된 상태별 검수 페이지와 최초 검수 차수 생성, 기존 좌우 비교에 연결.
4. 접수·파일·연결·확인·변경 기록의 DB 저장. 원본 PNG는 고유 파일명으로 로컬 보존하며 경로와 식별값을 DB에 기록. 재접수나 재연결로 원본 파일을 덮어쓰지 않는다.
5. 공식 번호가 없는 화면은 내부 식별자로 조회하고 화면에 ‘미정’을 표시. 기존 공식 번호 주소는 유지한다. 번호 없이도 작업 가능하도록 현재 필수 번호 제약과 조회 경로를 보완한다.
6. 현재 화면 단위 Figma 참조 스텁에 더해 페이지별 연결 및 가져온 디자인 이미지의 시점을 기록한다. 원본이 나중에 바뀌어도 비교 중인 이미지가 자동 교체되지 않게 한다.
7. 파일 처리·Figma 읽기·DB 저장을 화면 출력 코드와 분리한다. 포털 접속은 현재처럼 내 PC에서만 한다.

Figma 실제 접근과 포털의 인증 방식은 아직 검증하지 않았다. 구현 첫 검문소에서 무료 읽기 경로와 필요한 권한을 확인한다. 에이전트가 Figma를 읽을 수 있는 것과 로컬 포털이 직접 읽을 수 있는 것은 별개다. 인증정보는 화면 소스·DB·기록에 넣지 않고 로컬 설정으로 분리한다. 연결이 막히면 실제 이미지를 가져온 것처럼 꾸미지 않고 제한을 보고한다.

## 이번 범위에서 보존할 조건

- 촬영기 개조, 휴대폰 직접 제어, 로그인·다중 사용자, 설치 묶음, 공개 배포 없음.
- 자동 오류 판정, OCR, 자동 매칭, 자동 정렬·잘라내기 없음. 상태바·하단바·키보드는 현재 원본 그대로 보여준다. 따라서 픽셀 정렬이나 정확한 차이 비교를 검증한 결과물이 아니다.
- 사진은 외부로 전송하지 않는다. Figma 원본 디자인은 읽기만 한다.
- 공식 번호 발급, 재검수 차수 추가, A4 개선, 발행 기능 없음.
- 기존 웹 검수 데이터와 촬영 원본을 덮어쓰지 않는다. 별도 시험 DB에서 검증한 뒤 적용을 판단한다.

## 구현 후 분리 검증 기준

별도 검증자가 다음을 확인한다.

- 10장 접수 기록 보존, 로그인 8장 대상·찾기 2장 제외가 맞는지.
- 번호가 미정이어도 접수·재개·짝 확인·상세 진입이 되는지.
- 같은 디자인의 재사용, 시안 없는 상태의 보류, 일부만 확인 후 진입이 되는지.
- 잘못된 링크·권한 오류·누락 파일·중복 접수가 성공으로 표시되지 않는지.
- 재시작 후 자료와 연결 확인 기록이 남고, 재연결 전 이력도 남는지.
- 연결 확인만으로 PASS나 오류가 생성되지 않고 기존 웹 검수 기능이 유지되는지.
