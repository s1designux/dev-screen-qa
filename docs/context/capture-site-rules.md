앱 개발화면 촬영기에 **브라우저 사이트**(`capture-app/site.sh` → localhost:8767)와
**Figma 플러그인**(`capture-app/plugin-pick/`)을 붙였다. 2026-09-09 확정.

흐름: ① 디자인 고르기 → ② 찍을 목록 → ③ 조건 확인 → ④ 전체 촬영 → 검수로 보내기.

굳힌 결정(자세한 건 `capture-app/규칙.md` 한 장에 정리됨):
- **디자인은 Figma에서 드래그로 고른 것만** 플러그인이 보낸다. 이름 목록으로 고르면 웹/앱 시안을 헷갈린다(실제로 겪음).
  플러그인이 그림·글자·아이콘 자리·**시안 값(색·글꼴·크기…)** 까지 함께 보내므로 이 길에는 **Figma 토큰이 필요 없다.**
- 번호는 **캔버스에 놓인 차례**로 다시 매긴다(걸러내도 순서 유지).
- 같은 화면의 상태 변형은 앱을 껐다 켜지 않고 **이어서** 찍는다. 촬영 도구는 한 번만 띄운다(화면당 30초 → 6장 1분).
- **동작 칸이 비면 앞 장과 똑같은 사진이 찍힌다.** 그래서 `site/동작규칙.py`가 이름 뒷토막 + 시안 글자로 초안을 자동 생성한다.
- 검수 접수: 한 묶음 = 포털 화면 1개, 상태 하나 = 검수 페이지 1장. 포털 DB는 하루 한 번 백업 후 넣기만 한다.

- 사이트는 **launchd 로 저절로 뜬다** — `com.s1.capture-site`, 자리는 `~/dev-screen-qa/capture-app`.
  2026-09-14 워크트리를 한 폴더로 합치면서 이 자리가 없어진 옛 폴더를 가리켜 자동 시작이 죽어 있었다.
  폴더를 옮기면 `~/Library/LaunchAgents/com.s1.capture-site.plist` 도 같이 고쳐야 한다.
  고친 뒤에는 `capture-app/다시켜기.sh`(launchctl kickstart)로 다시 켠다.

**Why:** 디자이너가 Figma에서 눈으로 확인하고 원하는 만큼만 검수하도록 하려는 것. 사람 손이 더 가는 버튼은 만들지 않는다.
**How to apply:** 새 규칙은 코드에 흩지 말고 `규칙.md`와 `site/동작규칙.py`에 모은다. 관련: [[maestro-capture-plan]]
