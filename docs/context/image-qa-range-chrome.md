2026-09-02 river님 피드백 2건으로 만든 조각: ① 개발 캡처에 크롬 탭·주소창이 있으면 디자인의 가짜 탭바가 그것과 "짝"으로 잡혀 후보가 6→20개로 늘던 문제 → 양쪽 '틀 띠'를 찾아 제외하는 **검수 범위** 단계 추가(자동은 후보, 패널 '조정'에서 사람이 확정, 캡처 노드 pluginData `imageQaTopTrim`에 저장). ② 겹쳐보기로는 글자 대조가 어렵다 → 번호 선택 시 패널에 **나란히 보기**(디자인|개발 조각, 같은 배율) 추가.

- 재현 세트: `validation-image-qa/repro/dev_login_chrome_1920x1054.png` (헤드리스 캡처 위에 `make_chrome_capture.html`로 만든 120px 크롬 띠 합성). 실제 사용자 캡처 원본은 대화 이미지로만 받아 파일로 확보하지 못함.
- 결과: 크롬 사례 20→6개, 첫 사례(아이디 찾기 13개)·내용만 있는 로그인(6개)은 변화 없음.
- 설계 결정: 디자인에 틀이 없고 캡처에만 위쪽 띠가 있으면 **자동으로 자르지 않고 안내만** 한다(진짜 추가 요소일 수 있음). 아래쪽 띠(제스처바)는 캡처 쪽 자르기 미구현.
- 남은 문제(별건): 로그인 디자인의 사이트 헤더(101~157px)가 가짜 탭바와 같은 묶음 안에 있고, 헤더 구역 밀림이 dx -50~-67로 잡혀 로고 '누락'·"디자인에 없는 요소" 등 3건이 크롬 유무와 무관하게 남는다.

2026-09-02 후속(같은 세션): 나란히 보기를 **패널이 아니라 Figma 캔버스 카드**로 표시하도록 바꿈(패널 390px 유지). 카드는 그 번호와 같은 높이의 화면 바깥쪽(가까운 편)에 붙고 파란 연결선으로 이어짐. 캔버스에서 번호를 누르면 패널 목록이 그 번호로 따라감(code.js selectionchange → candidate-selected, 플러그인이 스스로 바꾼 선택은 500ms 무시). 겹쳐보기는 잘라낸 띠만큼 되돌리고 디자인 틀 띠를 잘라 '내용 맨 위끼리' 맞추도록 수정.

**Why:** 다음에 같은 화면·같은 증상을 볼 때 원인 분석을 반복하지 않고, 남은 헤더 3건이 크롬 문제가 아님을 바로 알기 위해.
**How to apply:** 브라우저 틀 관련 오탐 보고가 오면 먼저 패널 '검수 범위' 값(디자인/개발 캡처 제외 px)을 확인하게 안내한다. 재현은 `ELEMENTS_JSON=elements_login.json DESIGN_PNG=design_login_1920x1080.png DEV_PNG=dev_login_chrome_1920x1054.png DESIGN_MAX=4096 node run.js ../../plugin-image-qa/ui.html <out>`. 관련: [[image-qa-repro-findid]]
