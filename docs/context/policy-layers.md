검수 규칙의 **알고리즘**은 `plugin-image-qa/ui.html`에, **값**은 포털 DB `policy_rule`에 둔다
(`mvp0/policy.py` · 화면 `mvp0/policy_ui.py` → `/policy`).
층은 **시스템 → 서비스(프로젝트) → 화면 → 요소** 넷. river가 "서비스마다 같은 것·다른 것이 있다"고
해서 원래 3계층에 서비스 층을 더했다(2026-09-11).

- 포털이 원본, 피그마 프레임의 `qa_settings`는 거울. 포털 행이 있으면 포털 행이 이긴다.
- 사람이 후보를 '가변'·'제외'로 내리면 요소 층에 저절로 쌓인다(`auto_inspect._remember`).
- 값은 append-only, null = 그 층 예외를 거둠.

**river가 원하는 최종 그림(2026-09-11 대화):** 쌓기만 하면 창고고, **스스로 뒤져서 제안해야 도구**다.
합의한 순서 — ① 층 쌓기(완료·커밋 4f323bf) ② 검수기↔포털 배선(완료·커밋 701003a, `mvp0/policy_api.py`)
③ 판정을 규칙에 붙여 기록(**다음 세션에서 시작** — river가 2026-09-14에 신규 세션으로 하자고 함)
④ **규칙 발굴 엔진(로컬)** — 판정 기록을 뒤져 "같은 판정을 손으로 반복하는 자리"를 찾아 규칙을 제안
⑤ 제안은 **옛 화면 전부에 다시 돌린 검증 숫자와 함께**(볼 것 N→M, 정답 유지) 보여 주고 사람이 누른다.

**Why:** river가 손으로 찾던 패턴을 빨리 잡아 규칙으로 만드는 것이 검수 정확도의 핵심이라고 못 박았다.
로컬 비전 AI는 ④에서만 쓴다(사용자 기능 아님 — [[local-ai-decision]]).

**배선에서 걸렸던 것:** 파일 이름의 한글이 DB엔 NFD(자모 풀림), 피그마엔 NFC로 들어와 같은 파일을 못 알아봤다.
`design_receive.nfc()`로 맞춘다. 이름 비교는 꼭 하나만 맞을 때만 인정한다.

**How to apply:** 새 규칙을 만들 때 값은 CATALOG에 추가해 층으로 정하게 하고, 코드에 상수로 박지 않는다.
④가 쓸 만해지려면 판정 기록이 쌓여야 해서, 실제 검수를 몇 화면 더 한 뒤가 적기다.
