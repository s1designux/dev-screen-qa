**프로젝트:** dev-screen-qa (Figma 플러그인) — 피그마 최종 디자인(정답) vs 개발화면 실측을 대조하는 QA 도구.

**새 방식 (2026-07-07 확정):** 정답값(피그마 값·토큰)을 파일로 미리 빼지 않고, 비교하는 순간 플러그인이 피그마에서 라이브로 읽는다. 패키지 내보내기 단계 제거 → 흐름 간소화. 개발자→디자이너에게 넘기는 건 "어떤 화면을 어떤 폭(예 1440px)에서"만.

**검증 완료 (2026-07-07):** validation/ 폴더의 예시로 새 방식이 됨을 증명. 일부러 심은 결함 10개 전부 자동 검출.
- 속성(색·글자크기·굵기·모서리·여백)·크기·가로위치·요소 존재: 완벽, 헛경보 0.
- **약점 = 세로 위치:** 요소 하나 추가/삭제되면 그 아래가 줄줄이 밀림(cascade). river 결정 → 이 밀림은 개별 오류로 세지 말고 **원인(추가/삭제된 요소) 밑으로 묶어** 표시.
- 측정 스키마는 collect.js 형식(qa 이름표, box, style). 피그마 레이어 이름 = 개발쪽 data-qa 이름표로 맞춰 자동매칭.

**피그마 정답 예시 파일:** "검수 검증 · 예시 대시보드(정답)", fileKey `〔따로 보관: 피그마파일-2〕` (s1designux 계정, s1design 팀 〔따로 보관: 피그마팀-1〕 드래프트). design.html 설계도 그대로 1440px 대시보드로 구현.

**값 검수 플러그인 v1 완성 (2026-07-07):** `plugin-value-qa/` 폴더에 깔끔한 새 플러그인으로 구현(기존 이미지 방식 플러그인은 루트에 그대로 둠). code.js=정답 프레임 이름표 레이어 라이브 읽기(외부통신 없음, 원→radius999 처리), ui.html=정답읽기+개발JSON임포트+종류별대조+밀림여파묶기 리포트. 실제 피그마 파일로 검증 완료. 매칭 규칙: 피그마 레이어 이름 = 개발 data-qa, content/로 시작하면 위치·크기만.

**태그 없는 자동 짝맞춤 추가 (2026-07-08):** river 제약 = 개발소스 공유 불가(보안)+river가 개발화면서 실행 어려움, 단 "개발자에게 콘솔 1번 붙여넣기까지는 부탁 가능". 그래서 태그(data-qa) 없이 감. collect.js를 '모든 의미있는 요소 측정' 버전으로 바꿈. 플러그인이 글자·종류·위치(왼쪽위모서리)·크기(글자는 높이만)로 자동 짝맞춤→확신도%표시→river가 틀린것만 확인/수동지정→값대조. '이미 짝지어진 상자 안 요소는 구조차이서 제외'로 헛것 정리. 검증: 이름표 무시 자동짝맞춤 17/17(100%), 결함10개 검출, 헤드리스 크롬 전과정 확인.

**다음 단계 후보:** ①불일치를 캔버스 핀 표시 ②이력/여러화면 관리(기존 플러그인 골격과 합치기) ③짝맞춤 정확도 개선(이미지·아이콘·많은요소).
