2026-09-22 river 확정. 촬영기·검수 포털이 따로 돌던 판을 **버전 3**으로 다시 세운다.

**흐름이 뒤집혔다.** 예전: 피그마 → 촬영기 → 접수하며 과제 자동 생성.
새것: **포털에서 과제 먼저 만들기**(이름·번호·화면코드·담당자) → 그 과제 안에서 촬영 → 검수.
접수가 이름으로 과제를 찾고 없으면 만들던 탓에 실자료에 사실상 같은 과제가 4개로 쪼개졌다.

**차수는 끌고 오지 않고 새로 돈다** (river 2026-09-22, CLAUDE.md §19 를 바꾼다).
2차는 새로 검수하되 1차 이력과 **견주어 보는** 화면을 둔다 — 사라짐 / 또 나옴 / 새로 생김 셋.
근거: dedup 으로 차수를 이은 적이 한 번도 없다(지적 18건 전부 1차).
주의: 1차에서 **사람 눈으로만** 잡은 지적은 2차 자동 검수에 안 올라와 조용히 사라진다 —
그래서 비교 화면은 참고가 아니라 안전장치다.

**담당자별 구조로 간다.** person 표는 이미 있다(로그인 없이 이름 고르기).
비어 있던 것은 과제에 담당자를 붙이는 칸 — 2026-09-22 에 `project.owner` 로 더했다.
여럿이 쓰려면 **한 대를 본 포털로 정하고** 나머지가 그 주소로 들어온다.

**옛 판(V2)** 은 `legacy/v2/` 에 코드·자료를 통째로 복사해 돌아가게 뒀다.
포트 8865(포털)·8868(촬영), 화면 오른쪽 위에 '옛 판 V2' 이름표, 자료함도 따로.
깃에는 올리지 않는다(코드는 이력에 있다). 켜기: `legacy/v2/옛판-켜기.command`.

**남은 것:** 과제 4개 합치기(접수가 과제를 고르게 바꾸는 것과 한 몸) ·
차수 묶음 화면(촬영+검수+결론) · 차수 비교 화면 · 촬영기를 과제마다 따로 기억하게 하기
(지금 `capture-app/site/작업.json` 이 작업 하나만 기억해 과제를 바꾸면 덮인다).
