Maestro(오픈소스 모바일 UI 자동화)를 **캡처 전용**으로 써서 앱 개발화면을 화면·상태별로 찍고,
포털 화면 ID(`CV-AND-012@empty.png`)로 개명해 디자인 원본 옆에 접수하는 "검수 전 세팅" 플랜.
플랜 한 장: 〔따로 보관: 작업창링크-1〕 (2026-09-09)

결정된 것(2026-09-08~09):
- 표 안 값·목록 건수 등 서버 데이터는 **예외**(고정하려 하지 않음)
- Maestro AI 자율 탐색 기능은 **사용 안 함**(외부 모델·폐쇄망·자동확정 금지 원칙)
- 배포는 **설치 묶음(각자 PC, 맥용·윈도우용)**. 촬영 PC 한 대 방식은 채택 안 함
- iOS는 시뮬레이터(맥+Xcode 필요), 실기기는 비권장
- 미결: 착수 시점(기본은 검수 정책 조각 후), 첫 대상 앱·화면 5개, 플랫폼 순서(기본 안드로이드 먼저)

**Why:** 20번 방침(앱 캡처 기준 3겹)의 1겹 "캡처 가이드"를 사람 규율 대신 도구로 강제하려는 것. 개발자가 "Maestro가 알아서 이해한다"고 한 말은 절반만 맞음(글자로 요소 찾기·자동 대기·Studio 자동 대본; 자율 탐색은 AI 기능).
**How to apply:** 착수 시 조각 A(대본·촬영·개명, 별도 폴더 `capture-app/`) → B(포털 접수함·검수 전 점검) → C(실앱 5화면 10장 판정) → D(설치 묶음). 관련: [[image-qa-policy-rules]]

추가 결정(2026-09-09): **검수는 웹(포털)에서, 피그마 플러그인은 보조.** 캡처 접수함·검수 전 점검은 포털에 만든다.
촬영 결과 폴더의 이름 규칙(화면ID@상태)만 지키면 플러그인도 같은 폴더를 읽을 수 있게 둔다.
그룹원에게 필요한 것은 촬영기(설치)와 포털(브라우저)뿐 — 클로드는 제작 중에만 쓰인다.

추가 결정(2026-09-09 후반): **찍기 전 설정 단계(0단계)** — 폰(실제·가상 여러 대 중 선택, 해상도는 폰 그대로) · 깊이(주요 화면만 / 세부 동작까지 / 시나리오) · 계정 고르기.
**공통 시나리오 방식** — 공통 뼈대 대본 1개 + 앱마다 이름표 1장(앱 이름·로그인 버튼·메뉴↔화면번호·계정) + 특이 앱만 덧댐. "새 앱 추가 = 이름표 1장"이 목표.
권고: 실제 아이폰은 비권장(서명·불안정), 갤럭시는 글꼴 검수 때문에 실제 1대를 기준 폰으로. 미결: 기준 폰(실제 갤럭시 / 가상만).

작업 폴더 결정(2026-09-09): 검수 정책 조각과 커밋이 엮이지 않도록 **별도 작업 폴더**에서 만든다.
`(이 프로젝트 폴더)-capture` (브랜치 `feat/app-capture`, 코드는 `capture-app/`).
촬영기(A·A2·D)는 포털 밖 독립 프로그램이라 병합 없이도 성립하고, 포털에 붙는 것은 B 조각(접수함·검수 전 점검)뿐이다.
촬영기↔포털 접점은 **사진 이름 규칙(화면ID@상태)** 하나뿐 — 프로그램끼리 직접 연결하지 않는다.

**조각 A 완료(2026-09-09):** `dev-screen-qa-capture/capture-app/` 에 촬영기 1차 완성.
