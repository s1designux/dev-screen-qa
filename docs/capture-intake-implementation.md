## 확인용 포털

원래 프로젝트의 DB는 SQLite 읽기 전용 연결로 복사했으며 원본을 덮어쓰지 않았다.
촬영기 폴더와 Figma 원본도 수정하지 않았다.

- 주소: http://127.0.0.1:8771/intake
- 다시 실행: 이 작업 폴더의 `mvp0/preview.command` 더블클릭. 이미 켜져 있으면 기존 주소를 연다.
- DB와 이미지 파일은 로컬 생성물로 Git에서 제외한다. 실행 스크립트는 이 PC의 시험 DB가 있을 때만 동작한다.
- 다른 개발 환경에서는 `python3 mvp0/load_fixture.py mvp0/fixtures/tb-web-001.json mvp0/mvp0-real.db`로 기존 픽스처 DB를 만들고 `python3 mvp0/portal.py` 실행. 기본 주소는 127.0.0.1:8765.
- DB, 파일 저장소, 포트는 각각 QA_PORTAL_DB, QA_PORTAL_UPLOADS, QA_PORTAL_PORT 환경변수로 분리했다.

## 구현한 흐름

1. 화면 목록에서 촬영본 가져오기 또는 접수함 진입.
2. 폴더 또는 PNG 여러 장과 찍은목록.json을 함께 가져오기. 촬영기의 ‘찍힌것’ 형식과 탐색 촬영의 ‘촬영본’ 형식을 모두 읽는다. 파일명은 이름 제안용이며 파일 경로로 실행하거나 열지 않는다.
3. 프로젝트·플랫폼을 지정하고 화면 이름·상태·대상·보류/제외 사유를 저장. 같은 자료 재접수는 기존 접수로 안내. 누락·손상은 해당 항목에 표시.
4. Figma 시안을 선택해 촬영본과 나란히 표시. 사람이 ‘이 짝으로 확인하고 다음’을 눌러야 확인된다.
5. 확인된 항목만 기존 검수 페이지와 최초 차수로 등록한다. 미검수·이슈 0건으로 시작한다. 같은 모습으로 돌아온 상태도 별도 페이지이며 같은 디자인을 사용할 수 있다.
6. 시작 전 연결 변경은 재확인 필요. 시작 후에도 지적이 없는 페이지의 디자인 변경은 재확인 후 반영한다. 지적이 생긴 페이지의 디자인 교체와 촬영본 교체는 이번 조각에서 막아 기존 근거를 보존한다.

공식 화면 번호는 생성하지 않는다. 기존 DB의 필수 텍스트 제약은 유지하고 미정값은 빈 값으로 저장한다. 화면에는 ‘미정’, 내부 주소에는 UUID를 사용한다. 기존 공식 번호 주소도 유지한다.

## 이번 실제 자료

- ADB 탐색 촬영 결과 10장 접수. 자동 반복 대본 검증을 의미하지 않는다.
- 로그인 8장 대상, 찾기 2장 제외. 사유는 본문 미표시·원인 미확인.
- 사용자가 Figma에서 선택해 둔 로그인 관련 시안 10개를 읽기 전용 도구로 가져와 시험 DB에 저장했다. Figma 링크가 가리키는 것은 큰 페이지이며, 선택된 10개와 구별했다.
- PNG는 Figma 읽기 도구의 스냅샷이다. 가져온 시점과 도구 출처를 기록했다. 현재의 Figma 내용으로 자동 갱신되지 않는다.
- 로그인 기본 시안만 선택 대기 상태로 준비했다. 실제 자료의 사람 확인은 0/8. 오류나 PASS를 자동 생성하지 않았다.

## Figma 직접 읽기와 제한

로컬 포털에는 Figma REST 파일/노드 조회와 PNG 가져오기를 구현했다. 개별 프레임 또는 작은 페이지·섹션 링크를 지원한다. 24개보다 큰 범위는 좁은 링크로 안내한다. 가져온 시안의 파일·노드·이미지·버전·시점을 보존한다.

**이 PC의 포털 전용 읽기 연결 키는 아직 없어 실제 REST 인증 통신은 미검증이다.**
미리 준비한 10개 시안은 Codex의 Figma 연결로 읽은 것으로 포털의 직접 통신 성공을 뜻하지 않는다.

사용자는 연결 화면의 ‘Figma 읽기 연결 설정’에서 개인 읽기 키를 넣을 수 있다. 키는 실행 메모리에만 두고 DB·HTML·파일·이력에 저장하지 않는다. 서버를 종료하면 사라진다. 실행 환경의 FIGMA_ACCESS_TOKEN을 사용할 수도 있다. 토큰 없음·권한 오류·대상 없음·요청 제한·네트워크 실패는 성공으로 표시하지 않는다.

공식 참고: [Figma 인증](https://developers.figma.com/docs/rest-api/authentication/), [파일·이미지 조회](https://developers.figma.com/docs/rest-api/file-endpoints/).


- 접수·중복·누락·손상, 실제 10장/8대상/2제외, 보류·이름변경·오래된 창 충돌.
- 사람 확인 전 검수 시작 금지, 일부 시작, 같은 디자인 재사용, 재연결, 재시작, 파일·이력 보존.

- 다른 접수 항목 변조·외부 출처 저장·CSRF 차단, multipart와 용량 제한.

독립 테스트 19개 통과 시점을 기준으로 기록했다. 브라우저에서 제작자가 기본 시안 선택 저장을 관찰했다. 처음 발생한 Origin 오류는 응답의 Referrer-Policy를 same-origin으로 수정해 해소했다. 제공한 화면 캡처의 좌우 이미지·대기 상태는 별도 검증자가 확인했다. 실인증 통신·좁은 화면 배치·브라우저 전체 사용자 흐름은 독립 검증 완료로 주장하지 않는다.

## 코드 역할

- intake_store.py: 접수·원본 파일·짝 연결·추가 이력·검수 페이지 생성.
- figma_reader.py: Figma 읽기 통신과 오류 처리.
- intake_http.py: 파일 업로드, 요청 검증, 동작 처리.
- intake_ui.py: 가져오기·접수함·연결 화면 출력.
- portal.py / queries.py: 기존 화면 진입과 번호미정·미검수 표시 연결.

새 외부 라이브러리 설치 없이 Python 표준 라이브러리만 사용했다. 자동 매칭·OCR·자동 비교·자르기·휴대폰 제어·재검수 차수 추가는 구현하지 않았다.
