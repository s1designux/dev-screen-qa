## 수정한 사용자 흐름

**화면 목록 → 검수 페이지 목록 → 검수 상세**

- 처음은 항상 화면 목록. 기존 웹 검수와 가져온 로그인 화면이 프로젝트별로 함께 보인다.
- 화면 행은 페이지 수·짝 확인 수·검수 판정·미해결 수를 구별한다. 아직 짝을 확인하지 않아도 로그인 화면을 찾을 수 있다.
- 로그인 행을 열면 같은 화면의 상태 8개가 표로 나타난다. 각 페이지의 디자인 연결 상태와 검수 판정은 별개다.
- 페이지 상세는 좌 디자인/우 개발 이미지를 위에 고정하고 아래에서 검수 내용을 본다. 준비 중일 때도 이 틀을 사용한다.
- Figma 선택 목록·링크·연결 키 설정은 디자인 영역의 ‘Figma 연결·변경’을 누를 때만 여는 보조 창이다.
- 사람의 짝 확인 후 해당 페이지의 기존 검수 상세로 연결한다. 미확인 상태로 돌아가기 위해 중간 페이지 목록을 유지한다.
- 과거 UI에서 짝 확인만 하고 검수 시작을 하지 않은 자료도 ‘확인한 페이지 검수 열기’로 이어진다. 확인 이력을 임의로 되돌리거나 자동 재확인하지 않는다.
- 촬영본 가져오기는 목록의 보조 동작, 가져온 기록은 이름/대상·제외 사유·원본·이력을 관리하는 보조 화면이다.
- 등록된 페이지가 생겨도 로그인 행은 중복 생성하지 않는다. 원본 데이터 모델은 그대로이며 준비 데이터와 기존 검수 페이지를 조회 시 묶는다.

단일 파일 `mvp0/issue_categories.py`에서 표시만 묶는다. 저장된 category·핀 번호·상태·이력은 변경하지 않는다. 이번에 후보 생성기나 자동 검수 규칙을 포털에 연결한 것은 아니다.

유형과 처리 상태를 구별한다. 미해결은 분류별 탭, 보류·수정완료 등은 ‘보류·확인 대기’, 종결은 ‘처리됨’ 탭에 나타난다. 예전처럼 미해결/종결 어느 쪽도 아닌 지적이 화면에서 사라지지 않는다.

## 보존 및 검증

색상·글꼴·버튼·카드의 기존 스타일을 사용한다. 원본 촬영본·디자인·기존 이력·사용자가 이미 확인한 상태를 보존한다. Figma 직접 인증 통신은 이전과 같이 연결 키가 없어 실검증하지 않았으며 이번 변경 대상이 아니다.

독립 검증자가 임시 DB에서 24개 테스트를 통과했다. 기존 접수와 3단계 흐름·중복 방지·분류 및 이력 보존·Figma 보조 창·과거 확인 자료의 이어가기를 포함한다. 제작자는 실제 브라우저에서 목록→상태표→상세→선택창 열기/닫기와 기존 웹 검수의 핀·유형 탭·카드 표시를 관찰했다. 별도 검증자는 화면 캡처 4장의 구조·겹침·잘림을 확인했고 문제를 발견하지 못했다. 다른 창 크기와 전체 스크롤 동작은 독립 검증 완료로 주장하지 않는다. 실제 자료의 짝 확인이나 검수 시작을 검증 목적으로 누르지 않았다.

## 비교 보기 도구 (2026-09-09)

사용자 승인 범위에 따라 수동 검수 범위 지정은 보류하고, 준비·등록 상세에 공통 비교 도구를 추가했다.
- 나란히 / 겹쳐보기 / 부분 확대 전환. 양쪽 이미지가 있을 때 표시한다.
- 겹쳐보기는 디자인 농도 조정, 드래그·방향키 이동, 위치 초기화를 지원한다. 원본 비율을 유지하며 개발 이미지 너비에 맞춘다.
- 보기 위치는 페이지·차수·이미지별로 이 브라우저에만 저장한다. DB·핀·판정·이력을 수정하지 않는다.
- 개발 화면을 드래그하거나 기존 지적 번호·카드를 선택하면 두 조각의 확대 비교창을 연다. 디자인 위치는 화면 너비와 수동 보정 기준이며 자동 요소 정렬이 아니다.
- 자동 제외 룰, 자동 비교, Figma 실시간 값 읽기는 이번 범위에 포함되지 않는다.

독립 테스트 26개 통과. 모의 JS에서 드래그·방향키·초기화·확대 및 핀 좌표 변환, 확대 캔버스 양축 상한을 확인했다. 실제 앱 상세에서 보기 전환·드래그 확대창을 확인했다.
