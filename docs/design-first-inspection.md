# 디자인 원본 기준 검수 흐름

2026-09-09 사용자 승인: 개발 캡처를 기준으로 디자인 시안을 늘리거나 대응시키지 않는다.
디자인 원본을 먼저 순서대로 등록하고, 각 시안에 도달할 TC를 만든 뒤 촬영 결과를 매칭한다.

## 실제 반영

- 기존 로그인 시안 10개를 Figma 페이지 GUI_계정_24.11.29의 같은 행 왼쪽→오른쪽 순서로 등록했다. 좌표·TC 초안은 `mvp0/plans/login_design_first.json`에 보관한다.
- 기본 시안은 이전 사람이 확인한 연결과 페이지를 유지한다. 활성 버튼 시안은 두칸 입력 캡처를 후보로만 둔다(포커스 차이 안내).
- 나머지 8개 시안은 TC와 준비 조건을 만들어 추가 촬영 대기에 넣었다. 정확히 같은 상태가 없는 캡처로 강제 매칭하지 않는다.
- 과거 캡처 중심 추천·이력은 삭제하지 않는다. 기존 접수의 페이지 목록과 연결 주소는 디자인 기준 목록으로 이어진다. 이전 자료는 ‘기존 촬영 원본·연결 이력’에서 확인한다.
- 실제 기본 확인 1 / 후보 확인 대기 1 / 추가 촬영 필요 8. 새로운 오류 자동 확정 없음.

## 작업 화면

화면 목록 → 디자인 순서의 페이지 목록 → 기존 공통 상세.
상세는 왼쪽 디자인 고정, 오른쪽 개발 캡처 선택/등록, 검수 영역에 TC·기대 모습·준비 조건·수정·추가 촬영 요청을 표시한다.
새로 시작할 때도 ‘디자인부터 검수 준비’에서 촬영본 없이 가져온 시안을 선택·순서 지정할 수 있다.
새로 등록한 일반 TC는 구체적 조작 경로를 보완해야 하는 초안이다.

## 촬영 연결

‘추가 촬영 대기’에서 ZIP으로 TC JSON·원본 시안·Python 촬영 도우미·사용안내를 내려받는다.
기존 capture-app은 앱 열기/메뉴 진입만 지원하므로 입력 상태 TC를 그대로 실행할 수 있다고 주장하지 않는다.
새 도우미 `capture_tc.py`는 사람이 TC대로 상태를 준비한 뒤 현재 Android 화면만 adb로 촬영한다.
언어 전환·오류 응답·계정 상태는 작업자가 테스트 환경에서 준비해야 한다. 자동 로그인 시도나 자동 계정 잠금은 없다.
실제 기기에서 새 도우미 실행은 아직 검증하지 않았다. iOS는 수동 PNG 등록 경로를 사용한다.

출력은 TC UUID 파일명과 `design-capture-results-v1` 찍은목록.json이다. 포털에서 묶음을 가져오면 TC별 시안에 연결되고 확인 대기가 된다.
PNG 단독으로 각 상세에 등록하는 경로도 있다. 원본은 새 파일로 저장하며 기존 이미지·판정·이력을 덮어쓰지 않는다.
한 묶음 DB 등록은 전체 트랜잭션이다. 잘못된 형식·다른 계획·누락/중복 TC·손상 PNG·이전 revision은 차단한다.

검수 시작 후 캡처 교체/추가 촬영은 새 차수 기능의 영역이며 이번에 기존 차수를 덮어쓰지 않는다.

## 검증

독립 테스트 기존 30개 + 신규 16개 = 46개 통과.
범위: TC 원본 이력, 순서, 읽기시 DB 보존, 촬영 없는 시작, 파일묶음 내보내기, CSRF,
잘못된 입력 400, 스코프 검사, 추가 촬영→업로드→확인, 묶음 중간실패 rollback,
기존 업로드 우회 차단, 기존 URL에서도 공통 상세 유지.
실제 브라우저에서 디자인 목록·TC 상세·추가 촬영 대기 표시 확인.
추가 촬영 8건 자체의 실행이나 실제 Figma 직접 인증 통신을 완료했다고 주장하지 않는다.

### 디자인 추가·제외·복원
- 디자인 목록의 각 행에서 제외하면 활성 목록 및 추가 촬영 대기에서 숨긴다.
- 디자인 원본, TC, 촬영본, 연결된 검수 페이지와 이력은 삭제하지 않는다. 제외·복원 이벤트를 기록하고 동시 수정은 revision으로 차단한다.
- `디자인 추가·복원`에서 제외한 항목을 기존 순서와 내용 그대로 복원한다.
- 가져온 디자인 선택 또는 새 원본 PNG 등록으로 현재 목록 마지막에 디자인과 TC 초안을 추가한다. 새 TC는 실제 촬영 전에 구체적인 절차를 보완한다.
- 제외된 디자인은 복원하기 전 TC 수정·촬영본 연결·확인을 차단한다.

### 개발 캡처 추천
- 브라우저에서 같은 목록의 PNG를 축소하여 형태·색상 차이가 적은 순으로 제안한다. 외부 API와 DB 변경 없이 미연결 페이지에 첫 후보를 미리 보여준다.
- 후보 순위는 상태 일치나 정확도 확률이 아니다. 글자·입력·오류 상태는 사람이 확인한다. 기존 연결을 자동 교체하거나 촬영 대기를 자동 해제하지 않는다.
- 추천 팝업은 좌우 비교, 가로 스크롤 후보 목록, 하단 선택 버튼을 분리한다. 선택 저장 후 TC 영역의 검수 시작 버튼으로 확인한다.

### 기본 연결 저장 (사용자 요청)
- 현재 로그인 10개 디자인은 담당 에이전트가 입력칸·비밀번호 표시·버튼 상태를 대조해 가장 가까운 개발 캡처를 DB에 연결했다. 기존 기본 화면 연결은 유지했다.
- 영어·오류 문구·포커스 등 정확한 상태가 없는 8개는 기본 연결과 별도로 추가 촬영 대기를 유지한다. 연결 저장은 검수 통과를 뜻하지 않는다.
- 담당자는 팝업에서 기본 연결을 바꾼다. 이미 검수 페이지가 있어도 지적이 없으면 변경 가능하며 이전 촬영 기록은 이벤트로 보존한다. 지적이 있으면 새 차수가 필요하다.
