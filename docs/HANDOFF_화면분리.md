# [새 세션용] 검수 페이지를 별도 화면으로 분리하는 기능 (river 확정 2026-09-15)

## 0. 먼저 할 일
- 저장소 뿌리의 `CLAUDE.md` 를 읽고 그 규칙을 전제로 삼는다(특히 2번 절대 원칙, 4번 하지 말 것, 12번 작업 규율).
- 이 쪽지는 **다음 조각 하나**만 다룬다. 범위를 넓히지 않는다.

## 1. 왜 필요한가 (2026-09-15 실측)
촬영기가 홈 화면 4장(`웹_홈_로그인 시` · `최근 검색어 영역 노출` · `사업장 선택 메뉴 확장` · `버스시간표 다운로드 팝업 노출`)을
포털로 보냈더니 **로그인 화면**(`UVIS_USER_PC-WEB-001`) 밑의 검수 페이지 9~12번으로 붙었다.
까닭: `capture-app/site/intake.py` 접수()가 화면 사람키를 `{서비스코드}-{WEB|AND|APP}-{첫 화면번호}` 로 짓는데,
홈 촬영 목록도 번호가 001 부터 시작해 로그인 묶음과 같은 키가 됐다(같은 키 → 같은 screen 에 페이지만 추가).

river 결정: **내가 미리 나눠 주지 않는다. 사용자가 필요할 때 포털에서 직접 나눌 수 있는 기능**을 만든다.
(화면 = 스토리보드 ID 단위여야 하고, 어디서 끊을지는 디자이너가 안다 — CLAUDE.md 7번.)

## 2. 만들 것 (포털 쪽, `mvp0/`)
검수 페이지 목록(`/screen/<human_key>`)에서 페이지 여러 장을 골라 **"새 화면으로 옮기기"**.
- 고른 페이지들이 **새 screen** 으로 옮겨진다. 새 사람키는 같은 접두(`UVIS_USER_PC-WEB-`)에 **비어 있는 다음 번호**를 제안하고
  사람이 고칠 수 있게 한다(예: `UVIS_USER_PC-WEB-002`). 화면 이름은 페이지 이름의 공통 뿌리(`홈`)를 제안한다.
- 같이 옮겨야 하는 것(모두 `screen_id` 를 가진다 — `mvp0/schema.sql` · `design_plan.py` · `rule_log.py` 참고):
  `inspection_page` · `inspection_run` · `inspection_issue` · `issue_history`(issue 를 따라감) · `auto_run` · `auto_candidate`(+event) ·
  `auto_range` · `page_design_link`/`page_design_event` · `design_elements` · `rule_verdict.screen_id` · `policy_rule` 의 화면 층(있으면).
  **지우지 않는다** — `screen_id` 만 바꾸고, 옮긴 사실은 append-only 이벤트(예: `page_move_event`: page_id, from_screen, to_screen, actor, at, note)로 남긴다.
- 이미 있는 화면으로 **합치기**(옮길 곳을 새 화면이 아니라 기존 화면에서 고르기)도 같은 단추로 된다 — 한 흐름에 두 갈래.
- 접수 쪽은 건드리지 않아도 되지만, 재발을 줄이려면 `intake.py` 사람키를 `{서비스코드}-{자리표}-{첫번호}` 대신
  **묶음 이름(화면묶음)이 다르면 다른 키**로 짓는 안을 검토한다(단, 이미 들어간 데이터는 그대로 두고 옮기기 기능으로 정리).

## 3. 하지 말 것
- 옮길 때 이력·후보·판정을 지우거나 새로 만들지 않는다(2번-3 이력 삭제 금지). 옛 회차·옛 시안 판도 그대로 따라간다.
- 자동으로 화면을 나누지 않는다(이름 뿌리로 짐작해 미리 쪼개기 금지). 제안만 하고 사람이 누른다.
- 화면 사람키를 코드로 강제 재부여하지 않는다. 사람키는 라벨, 참조는 uuid(7번).

## 4. 검증 기준
- 실데이터 `mvp0/mvp0-real.db`(먼저 `mvp0-real.db.bak-화면분리전-<날짜>` 로 복사) 에서 홈 4장을 `UVIS_USER_PC-WEB-002 · 홈` 으로 옮긴 뒤:
  ① 두 화면 목록에 8장 / 4장 ② 옮긴 페이지 상세를 열면 후보(값 대조 49 · 그림 검수 포함 수정필요 117, 제외 6 — 사업장 메뉴 확장 기준)가 **그대로** 보인다
  ③ `page_move_event` 에 4행 ④ 수정요청서(`/fixdoc`)가 새 화면 기준으로 나온다 ⑤ 되돌리기(다시 WEB-001 로 옮기기)도 같은 단추로 된다.
- 검증은 만든 사람이 아닌 별도 주체(서브에이전트)가 한다(12번 maker ≠ verifier).
