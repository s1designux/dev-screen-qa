## 2. 무엇을 하기로 했나 (river 승인 2026-09-21)

**길 가 — 촬영 창 높이를 시안에 맞춘다.** 검수기는 건드리지 않는다.

고른 이유: 규칙이 틀린 게 아니라 **자료가 서로 다른 자로 찍힌** 문제다.
검수기를 안 건드리니 화면 21장 회귀가 필요 없고, PC 웹 화면 전부가 같이 좋아진다.

버린 길 — **나 · 검수기가 구역마다 따로 맞추기**:
구역별 맞춤(`bandAlignment`)은 근거가 얇으면 일부러 안 켜게 막아 두었는데 이 화면이 딱 그 경우다.
그 빗장을 풀면 지금 잘 맞는 화면이 흔들린다. 높이를 못 맞추는 화면이 실제로 쌓이면 그때 근거를 갖춰 다시 올린다.

## 3. 다음 사람이 할 일

### 고칠 자리

`capture-app/lib/webshot.py` — 창 높이가 **900 으로 못 박혀** 있다. 세 군데.

```
387:  칸크기 = 쪽.viewport_size or {"width": 기본폭, "height": 900}
490:  칸 = 브라우저.new_context(viewport={"width": 폭, "height": 900})
523:  칸 = 브라우저.new_context(viewport={"width": 폭, "height": 900})
```

`capture-app/lib/계정확인.py:180` 에도 같은 900 이 있으나 이쪽은 로그인 확인용이라 굳이 안 맞춰도 된다.

Playwright 로 창을 직접 만들므로 높이를 정확히 줄 수 있다(OS·크롬 UI 영향 없음).

### 넘겨줄 값

**시안 프레임 높이 − 맨 위 가짜 크롬 틀 높이.** 이 화면이면 `1080 − 88 = 992`.

- 시안 요소 목록은 촬영 준비 사이트가 이미 들고 있다 → `capture-app/site/시안요소.py`
- 크롬 틀을 가리는 규칙은 검수기의 `designChrome`(`engine/ui.html` 1022줄 언저리).
  촬영 시점에는 검수기를 안 돌리므로, **맨 위에 걸친 가로로 꽉 찬 사각형 중 이름이 브라우저 틀인 것**을
  같은 기준으로 찾아 빼면 된다.

### 조심할 것

- **시안이 스크롤 페이지처럼 아주 길면 상한이 필요하다.** 창 높이를 3000px 로 열 수는 없다.
  상한을 넘으면 지금처럼 900 으로 두고, 그 화면은 정렬이 어긋날 수 있다고 알린다.
- 높이를 바꾸면 반응형 화면은 배치가 달라질 수 있다 — 바꾼 뒤 눈으로 한 번 본다.
- 이미 찍은 사진은 소급되지 않는다. **이 화면은 다시 찍어야** 확인된다.

### 확인하는 법

1. 촬영기로 이 화면을 다시 찍는다(유비스사용자포털 로그인 화면).
2. 포털에서 페이지를 열어 `auto_run.alignment` 의 `ty` 가 0 언저리로 오는지,
   `rescued`·`thin` 이 꺼지는지 본다.
3. 양쪽 푸터가 다시 검수 범위 안에 들어오는지 본다.
4. 규칙 장부에 측정으로 쌓는다. 검수기를 안 고쳤으므로 화면 21장 회귀는 필요 없다.
