# 스토리보드 ID 작성 체계 (river 확정 2026-09-15)

> 검수 포털은 ID 를 **짓지 않는다**. UI 사양서에서 온 ID 를 사람이 적고, 포털은 그 이름을 보고 **묶기만** 한다.

## 1. 어디에 붙나
- 스토리보드 ID 는 **화면 한 장(검수 페이지)** 에 붙는다. 화면 묶음(screen)에 붙이지 않는다.
- 포털 검수 페이지 목록의 'ID' 칸에 적고 'ID 저장' 을 누른다. 비워 두면 '아직 ID 없음' 뭉치에 모인다.
- 저장 자리: `inspection_page.human_key` (묶음의 `screen.human_key` 와는 다른 칸).

## 2. 모양 — 무엇을 하는 화면인가가 ID 에 들어간다
```
uv-web-login001      서비스(uv) · 플랫폼(web) · 하는 일(login) · 번호(001)
uv-web-signin001     같은 서비스·플랫폼이라도 하는 일이 다르면 다른 무리
uv-web-findpw001
```
**번호는 하는 일 이름에 붙여 쓴다** (`login001`, `login-001` 아님).
포털이 무리를 가르는 자리가 거기다 — 붙여 쓴 숫자는 그 무리 안의 낱장 번호로 본다.

## 3. 포털이 묶는 법 (`mvp0/page_group.py`)
- **글자에 딱 붙은 끝 숫자는 낱장 번호**, 그 앞까지가 뭉치다.
  `uv-web-login001` · `uv-web-login002` → 한 뭉치 `uv-web-login`.
- **숫자가 구분자 뒤에 떨어져 있으면** 그 마디까지가 한 화면이다 → ID 전체가 뭉치 키.
  `UV-WEB-012` 와 `UV-WEB-013` 은 서로 다른 뭉치 (CLAUDE.md 7번 예시 체계도 그대로 산다).
- 상태 접미사 `@…` 는 떼고 본다: `uv-web-login001@empty` 는 `uv-web-login` 뭉치의 한 장 (7번).
- 대소문자·앞뒤 공백은 같은 것으로 본다. 목록에는 적은 글자 그대로 보인다.
- 뭉치 순서는 ID 순(숫자 마디는 숫자로 견준다). ID 없는 장은 맨 아래.

## 4. 시안 프레임 이름과 결 맞추기
검수는 **시안 프레임 이름**으로 들어오고(`웹_로그인 화면_비밀번호 숨김 상태`), 사양서는 **ID**로 말한다.

| 자리 | 누가 정하나 | 예 |
|---|---|---|
| 하는 일 + 번호 | UI 사양서 | `uv-web-login001` |
| 그 장이 어떤 상태인지 | 시안 프레임 이름 | `웹_로그인 화면_비밀번호 숨김 상태` |
| 한 장을 콕 집어야 할 때 | ID + `@상태` | `uv-web-login001@비밀번호 숨김` |

즉 **무리와 번호는 사양서가, 상태 이름은 시안이** 정한다. 포털은 무리로 묶고 상태 이름으로 장을 구별한다.

## 5. 하지 않는 것
- ID 를 자동으로 지어 넣지 않는다 (CLAUDE.md 2번-2).
- 프레임 이름을 ID 로 바꿔 쓰거나, ID 를 근거로 시안·페이지를 자동으로 나누지 않는다.
- 묶음(screen)의 사람키는 주소·라벨로만 남는다. 화면에서는 보이지 않는다.
